# 任务方案：Live2D 嘴部与眼部动画

## 任务事实与边界

### 表面任务

以用户提供的正脸照片制作移动端小屏使用的 Live2D 嘴部开合与双眼眨眼模型，并接入现有豆包实时语音网页，使正在播放的 AI 音频驱动嘴部幅度。

### 用户要求

- REQ-01：根据已讨论的 Live2D 路线实现嘴部与眼部运动。
- REQ-02：执行前先明确并补足美术静态资源和前置准备。
- REQ-03：用户主要在移动端小屏使用，明确知道画面是 AI 动画，不要求真人视频级效果。
- REQ-04：不允许 AI 重绘整张脸；AI 只能用于眼皮、口腔和隐藏皮肤的局部补绘。
- REQ-05：肖像权已由用户确认无需担心。
- REQ-06：用户于 2026-08-31 明确批准全部计划并授权执行。

### 约束

- C-01：原图未授权区域必须保持原始像素；不采用重新生成整张人物图、Talking Head 或扩散视频路线。
- C-02：首版仅实现 `ParamMouthOpenY`、`ParamEyeLOpen`、`ParamEyeROpen`；头部、视线、头发、身体和表情保持静止。
- C-03：嘴部必须由正在播放的音频时间轴驱动，不能按网络分片到达时刻驱动。
- C-04：现有 24 kHz PCM 播放、16 kHz 输入、自动判停和半双工状态机不得被破坏。
- C-05：当前图片可用于移动端 Stage 0；只有实测失败才升级源图，不把高分辨率原图设为硬前置。
- C-06：开发过程不得输出或记录密钥、真实语音正文或未脱敏的提供商数据。
- C-07：正式商用发布前单独确认 Live2D AI/Chatbot、Web 和 BtoBtoX 授权；本计划不授权发布或部署。

### 已核实事实

- F-01：用户提供图片为 636×821 正脸肖像，眼睛和嘴无遮挡，光线均匀，可作为移动端原型输入。
- F-02：原图为闭嘴、睁眼状态，口腔内部、闭眼眼皮和被遮挡皮肤没有可直接提取的像素。
- F-03：`apps/web/src/App.tsx` 已使用单个 `AudioContext` 将豆包返回的 24 kHz PCM 分片调度到单调播放时间轴。
- F-04：现有网页是 React/Vite，语音输入自动判停与半双工播放已经实现并有离线测试。
- F-05：项目尚无 Live2D 运行时依赖、模型资产或 Canvas 舞台。
- F-06：常见安装位置未发现 Live2D Cubism Editor 或 Photoshop；实际安装状态仍需在建模前确认。
- F-07：Live2D 官方工作流要求将可动部件拆分并补绘运动后暴露的隐藏区域，再导入 Cubism Editor 建模。
- F-08：Live2D 官方 Web SDK 提供按 WAV 音量实时驱动口形的示例，并提供 EyeBlink 组件。

### 未知项

### 暂定假设

## 关键挑战诊断

- D-01：真正限制交付的不是 Live2D 参数或音频接口，而是原照片缺少张嘴、闭眼时会暴露的像素；若直接拉伸原图，口腔、眼皮和皮肤会破洞或产生贴片感，并被后续建模与代码稳定放大。
- 支持链：F-01/F-02 证明输入只有闭嘴睁眼状态；F-07 证明运动前必须补绘隐藏区域；F-03/F-04 表明音频主链已经存在，软件侧不是当前首要缺口。
- 为何关键：美术底板一旦错误，继续优化音量平滑、帧率或 SDK 封装无法改善人物自然度；必须在模型和代码之前拦截。
- ALT-01 | 首要障碍可能是 Cubism 工具链不可得或与项目不兼容。证伪条件：官方样例和最小自有模型能在本项目构建、加载并渲染。
- ALT-02 | 首要障碍可能是 Live2D 对写实照片不适用。证伪条件：静态极限状态与移动端 Stage 0 经用户验收后没有明显破洞、变脸或不可接受的贴片感。

## 指导方针

- G-01 | 优先保护原始身份和像素一致性，以“原图拆层＋目标区域局部补绘＋静态极限状态闸门”为主线；只有美术资产通过后才投入 Cubism 建模和音频集成。发生冲突时，身份一致性与可回退性优先于动作数量和写实程度。
- 优先级：美术可行性 > Cubism 工具链可行性 > 模型参数正确性 > 实际播放同步 > 页面视觉收尾。
- AI 自主范围：可以生成目标局部候选、提取透明图层、组织项目资产、实现获批代码和运行本地验证；不得接受整脸漂移候选、公开发布、提交 Git 或代表用户接受商业许可。
- 必须询问条件：需要付费购买软件或许可、需要登录个人账号、需要扩大到头动/视线/表情、局部补绘无法通过身份一致性闸门、或必须改变既有音频协议。
- NG-01 | 不重绘整张脸、不生成多张完整人脸状态图，因为会引入身份和像素漂移。
- NG-02 | 不做真人视频、音素级口型、头部运动、全身物理、移动端跨浏览器全面兼容或生产部署，因为这些会稀释当前可验证目标。

## 近端目标与杠杆点

- O-01：在当前照片和现有网页上完成一个可本地运行的移动端嘴眼 Stage 0：模型只含三项标准参数，局部美术无整脸重绘，测试音频能连续驱嘴，随机眨眼不破图，现有语音测试与构建继续通过。
- 可行性：现有音频播放时间轴已可用；官方 SDK 有口形和眨眼机制；当前图像符合正脸原型条件。
- 减少的未知：验证局部补绘自然度、Cubism 工具链可得性、写实照片的移动端接受度和 Web 集成兼容性。
- L-01 | 把资源集中在一套可审查的嘴眼资产和一个隔离 Stage 0，而不是同时制作更多动作；这能最早暴露会使全链失效的美术问题。
- 杠杆失效信号：局部补图即使经过单变量迭代仍出现身份漂移或移动端明显贴片；此时停止 Live2D 扩张并回到 PNG 局部切换或其他视觉路线重新规划。
- 暂不追求：真人视频感、复杂表情、公开发布、商业授权完成和全平台兼容。

## 链式弱环节与风险

- W-01：局部隐藏区域补绘是美术链的最弱环；进入闸门为嘴眼静态极限状态通过蒙版外一致性与人工观感检查。失败则回到 A-02/A-03，不允许进入 Cubism 建模。
- W-02：Cubism Editor/Core 可得性和模型导出是运行链的最弱环；进入代码闸门为自有 `.moc3` 可被官方 Web 样例加载。失败则停止 A-06 以后工作，不用占位模型冒充完成。
- 串行理由：美术、模型、运行时、参数演示、音频同步依次消费前一步输出，属于链环结构，不能以并行产物数量替代质量门。
- 可并行范围：在不修改目标文件时，官方文档核对和测试设计可与局部资源评审并行；最终整合仍由 A-09 统一验收。
- 中止条件：整脸漂移、两轮局部补绘仍不自然、Cubism 工具链需要未批准付费/账号、或集成要求改变语音协议。
- 返工层：视觉破图回到输入/美术；参数不连续回到模型；播放回归回到 A-08；范围或权限改变回到 G-01/Q-01 重新规划。

## 假设与失败信号

- H-01 | 移动端小屏上，只有嘴眼运动的写实照片能达到用户认可的“AI 动画感”。预期观察：以目标宽度展示时，用户能辨识眨眼和说话且不首先注意到贴片边缘。最小验证：A-07 固定参数 Stage 0。通过标准：无明显破洞/变脸且用户接受。失败信号：用户即使在小屏仍认为嘴眼脱离脸部。失败后重查 D-01 与路线选择。
- H-02 | 读取同一 AudioContext 实际播放链的包络可让嘴部与声音保持主观同步。预期观察：声音开始时嘴同步起动，停顿和播放结束时闭合，没有随网络抖动抽动。最小验证：固定 WAV/PCM 加人工静音段。通过标准：嘴部事件顺序与播放时间线一致，主观偏差不超过约一帧到两帧。失败信号：嘴先于/晚于声音明显可见或分析节点引起音频回归。失败后重查 A-08 的时间轴与平滑参数。
