# 任务跟踪：AI 复活 Push-to-Talk 实时语音 Demo

## 任务目标与批准快照

- 目标：在 Windows Chrome 上交付可重复验证的单用户 Push-to-Talk demo；按住持续发送音频，松开触发本轮结束，模型流式返回并立即连续播放。
- 主要诊断：D-01；供应商鉴权/会话、输入 PCM 契约、流式传输和返回播放构成链环，直接全栈集成会掩盖故障层。
- 指导方针：G-01 风险先行纵向切片；G-02 按用户/开发工具/豆包/浏览器能力边界分工；G-03 用独立 provider adapter 隔离供应商变化。
- 近端目标：O-01；连续 10 轮至少 9 轮成功，松开到首声 P95 暂定不高于 3 秒，无明显变速、爆音、长断裂或串轮，并保留脱敏指标与复现步骤。
- 主动不做：NG-01 至 NG-03；本轮不做声音复刻、数字人脸部/嘴型、RAG、长期记忆、全双工、VAD、微信/移动端、多人并发、公开部署或提前引入 RTC/微服务。
- 批准依据：用户于 2026-08-29 接受完整 v1 基准，允许后续使用密钥；第一次需要真实握手时必须暂停，由用户自行把密钥导入未跟踪的本地 `.env`。
- 路由快照：不确定性高、依赖强、可逆性混合、范围膨胀风险明显、仓库从零开始、供应商环境动态中高、协调复杂度低；风险等级标准。
- 已选模块：M-01,M-02,M-03,M-04,M-05,M-07,M-08
- 用户步骤映射：S-01 -> A-01,A-02; S-02 -> A-03; S-03 -> A-04,A-05; S-04 -> A-06,A-07,A-08; S-05 -> A-09,A-10
