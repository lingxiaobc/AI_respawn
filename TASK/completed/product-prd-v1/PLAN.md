# 任务方案：AI Respawn 产品 PRD

## 任务事实与边界

- 表面任务：基于用户已经逐项确认的产品需求和仓库现状，编写一份可直接约束后续设计、开发和验收的产品 PRD。
- REQ-01：输出 Markdown PRD 到 `docs/product-prd.md`，作为产品范围与验收基线。
- REQ-02：系统分离管理员与普通用户的身份、入口和权限；管理员创建、删除、审核和发布角色，用户只能访问获授权角色并发起通话。
- REQ-03：管理员为角色提交单张照片、昵称、性格配置和音色复刻音频；系统异步处理并在管理员确认后发布。
- REQ-04：照片输入宽高比不固定，但必须单人、五官完整、近正脸、清晰且无遮挡；不合格时拒绝并说明原因。
- REQ-05：规范图可在缺肩时补肩并延展背景或衣服；管理员批准规范图后，运行时除嘴部和眼皮区域外其余像素不变。
- REQ-06：用户端不采集摄像头，只采集麦克风；通话为半双工、一问一答、自动判停，不支持打断和全双工。
- REQ-07：AI 输出音频实时播放并驱动嘴部张合幅度；嘴型只响应音量，不区分音素；眼皮偶尔自然眨动。
- REQ-08：静音时嘴巴自然闭合、非严肃、非明显抿嘴，可有极轻微微笑；不要求头部、身体、手势、复杂表情或真人级视频。
- REQ-09：同一角色可分配给多个用户；角色资源和基础性格共享，聊天记录与记忆按用户隔离。
- REQ-10：音色复刻失败时通知管理员并要求重新上传；复刻结果必须可试听并经管理员确认。
- REQ-11：面向中国大陆部署，以手机浏览器为主要使用端；当前业务规模约为每日新增或处理 5 个角色。
- REQ-12：PRD必须明确目标、非目标、流程、状态、功能、数据、验收、风险、待定项和变更控制，防止技术方案反向改写产品目标。
- C-01：本次只新增产品文档与获批任务跟踪文档，不修改应用代码、模型资产、配置、依赖或外部系统。
- C-02：Live2D 不是客户强制要求，PRD不得把它写成产品前提；它只能作为候选实现方式。
- C-03：参考图片只用于构图和效果理解，比例与分辨率不构成固定输入规格；不把下载目录中的原图复制进仓库。
- C-04 | 保存真人照片、声音和对话记忆涉及高敏感数据与外部合规约束，PRD必须设置授权、删除、访问控制和上线合规闸门，但不提供法律结论。
- F-01：仓库已有浏览器麦克风、半双工自动判停、豆包实时语音 WebSocket 网关、流式音频播放以及轻度 2D 嘴眼动画的本地演示基线。
- F-02：仓库验收资料表明，现有嘴部由 AI 输出音频分析器驱动，眼部仅开放左右眼参数，当前本地实时语音和 Live2D Stage 0 已完成验收。
- F-03：现有项目尚未具备正式的双端账号体系、持久化数据库、对象存储、异步角色生成管线、多角色授权、音色复刻管理、正式移动端发布和公网部署能力。
- F-04：用户已确认像素不变的比较基准是管理员批准后的规范图；规范化之前允许裁切、缩放和缺肩补全。
- F-05：根据已查阅的火山引擎官方说明，音色复刻流程需要先确定或生成 speaker ID，再上传音频训练并查询状态，后续以该 ID 调用合成或实时能力；具体接口字段仍以接入时官方文档为准。
- U-01：首发期允许的同时在线通话数、峰值并发和目标成本上限尚未确定。
- U-02：最终人像驱动实现采用 Live2D、定制 2D 图层还是其他方案尚未确定。
- U-03：正式域名、云厂商、短信或其他登录方式、数据保存期限和客服处理时限尚未确定。
- ASM-01：MVP 以当前约每日 5 个角色的运营规模设计，但上线前必须用实测容量覆盖用户确认的目标并发。
- ASM-02：管理员为上传照片和声音取得合法授权，并在产品中保存可审计的授权记录；若不能成立，相关角色不得发布。
- 可用输入、工具与权限：用户确认的需求、参考图片观察结果、仓库现有文档与代码、已查阅的火山引擎与中国大陆监管公开资料；具有在仓库内新增和编辑 Markdown 文件以及运行只读检查的权限。

- 不可逆性：混合

## 关键挑战诊断

- D-01：首要问题不是缺少功能清单，而是同一需求跨越原始照片、管理员批准的规范图、运行时动画、外部语音服务、角色发布与用户记忆隔离；如果不建立统一术语、状态、权限和可测试验收，开发会把候选技术当成产品要求，或者在各模块中采用相互矛盾的解释。
- 支持链：REQ-05 同时允许规范化阶段改变画面和运行时阶段保持像素不变；REQ-07 要求实时音频驱动而不是预生成视频；REQ-09 要求资源共享但记忆隔离；F-03 表明这些跨域能力尚未由现有系统统一承载。
- 为何关键：任何一处语义漂移都会导致不可组合的实现，例如把原图当像素基准会阻止补肩，把授权链接当权限会破坏隔离，把预生成视频当实时通话会直接偏离核心效果。
- ALT-01 | 主要问题是尚未选定 Live2D 或其他人像技术。证伪条件：即使技术路线确定，只要状态、权限和验收仍不统一，开发仍会产生范围和接口冲突，因此技术选型不是当前 PRD 的主要诊断。
- ALT-02 | 主要问题是需求仍然不足。证伪条件：用户已明确关键视觉、交互、运营和隔离要求；剩余未知主要是容量和供应商接入参数，可通过上线闸门与待定项管理，不阻止形成产品基线。
- 坏战略审计：不使用“体验好”“安全稳定”“后续扩展”等口号替代可测试要求；不把所有未来能力列为 MVP；不以单一实现方案伪装成用户需求；不隐藏并发、成本、合规和供应商限制等未知项。

## 指导方针

- G-01 | 建立一份技术中立、编号化、可追踪的产品单一事实源；每个核心要求必须落到角色、触发条件、状态变化、错误反馈和可观察验收。
- G-02 | 把产品硬要求、当前事实、候选技术、假设和待定决策分开书写；开发不得用候选实现替换产品效果，也不得把待定项默认为无限容量或已获授权。
- G-03 | 按“输入合格 → 资产生成完成 → 管理员批准 → 用户获授权 → 通话可用”的顺序设置发布闸门；任一上游未通过都不得进入下游可用状态。
- 优先级：先锁定用户价值和边界，再锁定流程与状态，然后锁定模块要求与验收，最后记录非功能门槛、风险和变更控制。
- AI 自主范围：可依据获批需求组织章节、分配需求编号、补充不改变需求的验收表述和错误状态；不得自行增加知识库、用户摄像头、打断、全双工、复杂表情、身体动作或新商业模式。
- 必须询问条件：任何新增能力、扩大数据用途、修改授权模型、改变像素不变基准、将候选技术升级为硬依赖、设定未经用户确认的并发或成本承诺，均需重新获得用户批准。
- NG-01 | 不在本次任务中编写或修改应用代码，因为当前目标是先形成产品基线，提前实现会绕过批准的验收边界。
- NG-02 | 不强制 Live2D，也不选择最终人像驱动方案，因为客户关注的是可验证效果，过早锁定会减少技术回退空间。
- NG-03 | MVP 不包含用户摄像头、用户表情识别、头部运动、身体或手势、复杂表情、音素口型、用户打断、全双工、背景音乐和知识库，因为这些能力不贡献当前核心验证且会显著扩大实时链路复杂度。

## 近端目标与杠杆点

- O-01 | 交付可被产品、设计、前端、后端、算法和测试共同引用的 PRD，使每个后续实现决策都能追溯到明确需求或待定项。
- O-02 | 把最易混淆的产品契约转化为状态、权限、数据归属和验收门槛，从文档层面阻止错误实现进入开发。
- 可行性：用户已经完成关键需求澄清，仓库已有当前技术基线和验收资料，本轮无需外部写操作或不可逆变更。
- 减少的未知或创造的选项：文档不会消除具体并发、云厂商和人像技术未知，但会给它们设置决策时点和不得越过的产品验收，使多个技术方案可以在同一标准下比较。
- L-01 | 最高杠杆是把“规范图”定义为管理员批准后的唯一动画基准，并把“共享角色资源”和“用户私有记忆”分成不同数据域；这两个定义同时稳定视觉管线、权限模型和测试方式。
- L-02 | 第二杠杆是需求 ID 与验收追踪矩阵，使范围变更必须显式修改受影响需求和验收，而不能散落在开发讨论中。
- 集中资源方式：只新增一个正式 PRD 和一个任务跟踪包；不创建技术设计、接口定义或页面代码。
- 杠杆失效信号：PRD出现无法从用户流程定位的功能、无法观察的验收词、相互冲突的状态、未标注的技术承诺，或无法区分共享资源与私有数据。
- 暂不追求的终局：完整商业化、多租户组织、无限并发、跨端原生应用、全双工数字人和最终供应商锁定。

## 链式弱环节与风险

- W-01 | 角色发布链依赖图片、音色、性格和管理员批准全部就绪。进入闸门是 A-01 术语固定；A-02 必须串行完成状态机后 A-03 才能写权限与异常；中止条件是出现未批准即可发布的路径；返工层级为 G-03 和 A-02。
- W-02 | 视觉验收依赖正确区分原图、规范图和运行时帧。进入闸门是 A-02 已定义规范图批准状态；A-04 串行锁定验收；中止条件是像素比较基准含糊或把实时动画误写成预生成视频；返工层级为 D-01、A-01 和 A-02。
- W-03 | 上线要求依赖外部供应商、监管规则和容量未知。进入闸门是 A-03/A-04 已明确数据和实时链路；A-05 不承诺无证据阈值；中止条件是将未知并发或法律判断写成已保证事实；返工层级为 U-01、C-04 和 A-05。
- 串并行理由：六个行动形成语义与状态的依赖链，单文档写作不因并行而获益；按顺序执行可减少后文反复重写。

## 假设与失败信号

- H-01 | 预期观察是独立阅读 PRD 的开发者能准确复述“实时音频驱动轻度 2D 人像”而不会理解成固定视频。最小验证是检索并人工复核产品定义、非目标和专项验收。通过标准是三处表述一致且不存在“预生成视频作为通话画面”的要求。失败信号是任一章节含糊使用“生成视频”却未解释运行时机制。失败后重查 D-01、G-01 和 A-01/A-04。
