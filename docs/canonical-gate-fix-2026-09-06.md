# 原图与标准图质量门禁修正（2026-09-06）

## 原因与定位

旧 `scripts/portrait-motion/preflight.py` 在规范化之前对上传原图运行人脸定位、五官几何和清晰度硬门槛。这将“原图不能可靠定位”错误等同于“规范化后的图也不能定位”，导致90多岁男性尚未得到标准图就被阻止。旧证据保留在 `AI_output/stability-v1/preflight-matrix.json`；它不能证明老人的标准图或动画不合格，也没有证据把这次拒绝归因于平台。

## 当前流程

原图文件有效性 → AI规范化 → 标准图严格定位/清晰度/遮罩校验 → 四态局部素材 → 动画组装和技术审计 → 用户确认。

- 原图检查仅限大小、允许格式、单帧、边长与完整解码，不再调用478点定位模型。报告明确 `stage=source-basic`、`facialQualityAssessed=false`。
- `prepare.py` 在读取或复用定位缓存之前，对标准图执行尺寸、不透明度、单人脸、478点几何、倾斜和局部清晰度检查。零人脸和多人脸错误给出检测数量，统一用 `CANONICAL_INVALID` 标明检查对象。
- 严格检查失败时，流水线在 `locate` 暂停，不进入任何donor请求；不通过AI识别猜测补证据，不自动付费重试。
- 独立复核发现缓存分支原先缺少额外眼线倾斜和遮罩重叠检查，已补齐，并增加新构建/缓存一致拒绝测试。原缓存、原图与历史产物不覆盖。
- 标准图身份相似、表情自然与流畅度并非这些启发式阈值能够保证，仍由用户确认。多人、模糊等原图通过基础检查不等于接受其人物效果；最终标准图必须通过门禁。
