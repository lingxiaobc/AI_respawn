# 管理员图片规范化

本阶段把管理员上传的人像编辑为后续眼睛/嘴巴定位可复用的统一输入。入口是本地页面 <http://127.0.0.1:5173/normalize>，也可以使用同一后端能力的串行命令。

## 固定合同

- 输出：1024×1536 PNG，每张输入只生成一张结果。
- 构图：单人正脸、头部与五官完整清晰、水平居中、头顶和两侧留少量空间、包含肩膀和上胸。
- 静音表情：自然放松，嘴巴自然闭合，不严肃、不明显抿嘴，可以有非常轻微的微笑。
- 保持：人物身份、年龄、五官、肤质、发型、衣服、色彩、光线和背景。
- 允许：为了统一构图轻微调整姿态；原图缺少肩膀时自然补全原服装和背景。
- 禁止：美颜、年轻化、瘦脸、磨皮、换五官、换发型、换衣服、换背景、证件照化和风格化。

规范化只降低输入差异，并不承诺眼睛或嘴巴位于固定像素坐标；下一阶段仍应使用人脸关键点定位。

## 输出结构

```text
AI_output/normalized/
├── .jobs/<任务 ID>.json
└── <安全文件名>-<输入 SHA-256 前 12 位>/
    ├── source.png
    ├── canonical.png
    └── metadata.json
```

`source.png` 是输入图片的无损 PNG 副本，不修改 `image/` 中的原文件。`metadata.json` 只记录哈希、尺寸、状态、模型参数版本和脱敏错误，不保存密钥、Authorization、Base64 或完整供应商响应。

## 本地页面

1. 在未跟踪的 `.env` 中设置 `ZENMUX_API_KEY`。
2. 运行 `npm run dev`。
3. 打开 <http://127.0.0.1:5173/normalize>。
4. 选择 1 至 10 张 PNG/JPEG/WebP；单张不超过 12 MiB、短边至少 512px。
5. 页面显示 queued、running、succeeded、failed 或 skipped，并并排展示原图与规范图。

该页面没有账号和审核流，只能用于本机开发。管理员应先目视确认五官完整清晰；自动人脸质量/身份验收不在本阶段。

## 批处理

先做完全离线的输入检查：

```powershell
npm run normalize:batch -- --dry-run image/青年.png image/老人2.png
```

真实处理必须明确列出文件，默认严格串行，已有成功内容会跳过，任一失败后停止且不会自动重试：

```powershell
npm run normalize:batch -- image/青年.png
```

不要在一次试验中用通配符扫描整个目录。网络超时可能代表供应商完成状态未知，此时先检查任务记录并由人工决定是否授权新调用。
