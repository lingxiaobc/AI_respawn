# 照片本地实时数字人通话

当前批量与通话规则见 [本机批量人物与通话阶段](BATCH_CALL_PHASE.md)。下方原单照片测试记录保留作为历史证据。

当前流程：上传照片 → ZenMux 保真规范取景 → 本地人脸定位、视频与人物资源制作 → 点击角色与绿色接听按钮 → 豆包实时语音回复 → 同一音频驱动本地嘴部推理及播放。新照片会发送至 ZenMux 及其上游生图服务，不发送给豆包；原有成品不自动重做。详见[当前角色管理与规范化规则](ROLE_MANAGEMENT_NORMALIZATION.md)。

## 本机启动

要求 Windows、Node.js 24+、Git、uv；首次 Python/CPU PyTorch 安装需要网络和本机磁盘空间。无需独立 GPU。

1. 项目根目录放置客户认可原型所用的 `epoch_40_new.pth`。本次验证文件 SHA-256：`1730b121d97c3f9429eace07cbf454d1b2862b76eeb32b84af8b028c6f5759b9`。安装脚本校验此文件，不静默替换权重。
2. `npm ci` 安装 Node 依赖；`npm run avatar:setup` 准备 `.cache/dh-prep-py312/` 和 `.cache/dh-live-upstream/`。上游固定为 `4467e97cd97194c2c54762043cf121c6d313db12`，使用既有 MediaPipe 照片定位方法；不跟随上游切换人脸定位方案。
3. 在本机 `.env` 设置 `DOUBAO_API_KEY`、`ZENMUX_API_KEY`、`IMAGE_MODEL_ID`、`ROLLBACK_MODEL`，声音沿用 `.env.example`。不要覆盖已有 `.env`，也不要提交密钥。
4. `npm run dev` 启动网关与网页；打开 <http://127.0.0.1:5173/>。
5. 选择 1—3 张照片开始制作，在成功角色卡片点击通话，然后点击绿色接听。允许麦克风后直接说话，连续静音约 1.2 秒提交；挂断返回列表。不需要摄像头权限。

默认网关端口 `8877`；本机 Windows 的 TCP 排除范围覆盖原端口 8787。`PORT` 可在 `.env` 修改，前端代理与网关共用该值。可选 `AVATAR_PYTHON`、`AVATAR_WEIGHTS` 指定本机解释器或权重绝对路径。上游缓存仍固定在项目 `.cache/dh-live-upstream`。

## 使用边界

- 每批最多三个人物，依次制作；当前批次结束前不能再上传新批次。成功角色随时可通话，制作任务为通话暂停，挂断清理后自动继续；后续每轮回复无需重新制作。
- 上传最多 12 MB，静态图片最短边至少 128 像素，总像素最多 2000 万；只接受检测到单个人脸且嘴部裁剪范围有效的照片。展示缩放至最长边不超过 960 像素，原照片文件保持不变。不承诺任意角度或遮挡照片均成功。
- 数据库保存在 `artifacts/avatars/avatars.sqlite`，资源保存在 `artifacts/avatars/<id>/`。刷新和重启恢复全部成功人物；失败不会替换已有可用人物。后台处理中刷新页面会继续显示状态；意外退出后未完成项标记中断，需手动重试。
- 每个图片模型请求最多等待 3 分钟，主失败回退一次；本地制作另有 3 分钟上限，不含排队和通话暂停。浏览器只服务明确列出的画面资源，不提供原图、标准图私有文件、处理关键点、模型或环境文件下载。
- 照片人物只在柔边嘴部椭圆内部变化，不添加头部、颈部、肩膀或眨眼动作，保留上游 MatesX 标识。使用固定示例时仍保留原示例眨眼。
- 半双工，AI 播放时不能插话。挂断会停止麦克风、音频、队列和连接，再次通话会重新初始化设备。
- 人物加载失败可使用纯语音；播放中失败可能丢失当前轮剩余声音，下一轮回退纯语音，尚不保证无缝接续。

## 验证入口与方法

主页面的人物就绪后，可进入角色对应的测试入口，或打开 `/?avatar-test&avatar=<角色ID>`。此页使用固定公开语音输入，发起三轮真实 API 调用并计费，不使用用户麦克风。

测试页分别记录每轮 ASR、PCM 字节数、播放样本数、队列排空、网关恢复 ready，以及嘴部连续采样的变化次数。嘴部按相邻采样帧比较，嘴部以外与初始画面对比。不能用一次非零口型系数或一次画面变化替代三轮验证；这些像素指标仍不能代替真人对同步和自然程度的主观评价。

自动检查：`npm test`、`npm run check`、`npm run build`、`npm run avatar:verify`、`git diff --check`。本仓库没有模板说明中的 `scripts/validate_codex_template.py` 或 `tests/`，实际检查采用本项目已有命令。

## 实现与迁移说明

- `scripts/prepare-avatar.py` 统一单照片制作接口，复用原先478关键点、80帧静态素材、80项人物特征及嘴部遮罩比例。随机种子固定，使同一环境的制作过程可复现。
- `apps/server/src/avatar-service.ts` 提供本机上传、处理状态和严格白名单资源服务；一次一个处理进程，工作进程环境不含豆包密钥。
- `PhotoUpload.tsx` 提供上传和处理状态，`App.tsx` 将成功人物接入既有 `AvatarPlayer`，旧 iframe 与轮次在替换时清理。
- 文本资源哈希统一按 LF 校验，适配 Windows Git 换行。历史 `qt-loader.js` 清单与实际文件不符；实际内容与固定上游保留的 loader 函数全文匹配后，已校正清单。WASM 与二进制素材未替换。
- 原三张照片离线实验脚本保留作为历史参考；新流程使用 `prepare-avatar.py`，无需手工运行旧脚本之间缺失的制作步骤。

移到另一台电脑时：Git 同步代码，单独迁移已认可权重和必要照片，重新运行环境准备命令，配置本机 `.env`。不会把 `.cache/`、个人照片、`.env` 或运行资源提交到 Git。
