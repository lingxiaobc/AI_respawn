# DH_live_mini 固定人物原型

分支：`codex/dh-live-mini`，基于 `codex/option2-APIcall`。目标是验证低固定成本的浏览器人物驱动，不需要新增 GPU 服务器或购买数字人订阅；豆包仍按原服务用量计费。

## 试用

1. 现有 `.env` 配置豆包后，项目根目录执行 `npm run dev`。
2. 打开 http://127.0.0.1:5173/ ，等待“人物已就绪”。点击“播放示例音频”，可离线于豆包观察固定人物；这一步不使用麦克风。
3. 点击“开始语音通话”，允许麦克风，直接说话。连续静音约 1.2 秒后回复；人物和语音播完后恢复监听。
4. 需要纯语音时，在开始通话前取消“显示数字人”。“结束通话”停止播放、录音和连接，再次通话点击“重新连接”。

只看本地人物可运行 `npm run dev:web`，无需启动网关。三轮真实集成测试入口为 http://127.0.0.1:5173/?avatar-test ，点击“运行三轮豆包测试”；使用已有 FSDD 公开样本，不采集麦克风，产生三轮真实 API 用量。

## 实现与边界

- 保留原豆包网关、24 kHz PCM16 输出和半双工会话协议。主页面由用户点击才打开网关连接。
- 新增连续 24→16 kHz 降采样，保留跨网络分片余数，320 ms 分片封装为 WAV。首个分片形成后即可播放，不等待整句话；相对原路径增加分片缓冲等待。
- 独立同源 iframe 隔离 Qt/WASM 全局变量；一份音频同时送入嘴型推理和 Web Audio，只有 iframe 发声。逐片 `onended` 串行推进，整轮结束才发送 `playback.done`。
- 校验消息来源/来源窗口/轮次，拒绝提前、重复或旧轮完成事件。停止清空音频和队列，45 秒结束等待及约 1 MB 待播队列上限避免无限等待和积压。
- 人物加载失败自动切换纯语音；若播放途中失败，本轮剩余人物音频可能丢弃，完成当前轮次后，下一轮使用纯语音，不承诺无缝接续。
- 嘴型受音频驱动；当前头部轮廓、颈部与身体固定，只有眼睑局部眨眼及脸部内部嘴型动画。本轮没有语义情绪控制，也没有任意照片生成资产的流程。
- 使用固定公开男性示例人物，保留 MatesX 标识。资源与 SHA-256 清单随代码保存，不运行时从第三方网站下载。上游版本和授权边界见 `apps/web/public/dh-live/PROVENANCE.md`；本次未购买授权，不能据此承诺商业用途免费。

## 尚需现场体验

这次没有用用户实际麦克风完成面对面听感验收，也未验证 Windows 外部 Chrome、手机、低性能设备或长时间运行。自动测试覆盖数据连续性与轮次控制，不能代替检查音色、口型准确度、绿幕边缘或面部自然程度。首次原型的头发绿边已在下述优化中处理；人物素材和人脸推理分辨率仍限制近距离观感。

建议先实际说短句、长句，观察回复首声、嘴型、停顿以及播完是否恢复聆听，再决定是否继续投入定制人物与画质优化。

## 观感优化：去绿边与小幅摆头（2026-09-07）

用户已认可原型嘴部效果，本次仅调整人物画面合成与静音底板视频速度，不改变 WASM、音频重采样、分片播放或轮次协议。

- 去绿移到嘴部合成之后，避免推理贴片重新带入绿色；消除原着色器去绿后混回原色的步骤，补充暗绿色边缘的透明度处理。只压制超出红/蓝通道的绿色，保留正常肤色。
- 利用素材每帧头部位置和侧倾，以整段素材的中位姿态为基准，保留 22% 的平移和侧倾幅度。处理作用于已合成的脸部，向脖子和肩膀平滑减弱，嘴巴随脸部一起变换，不对嘴型做时间平均。
- 静音人物视频播放速度为 0.65；音频仍按原速播放。眨眼等底板动作也随视频放慢。此处理是二维稳定，不是重新生成三维头部动作。
- 本素材计算得到的侧倾范围为 12.78° → 2.81°，头部锚点水平范围 13 → 2.86 像素、垂直范围 30 → 6.6 像素（720×1080 原始画布坐标）。这些是变换目标，不是独立视觉追踪精度保证。

验证：内置 Chromium 中比较同一第 132 帧的原幅度/稳定后画面，头部倾斜明显减小，发际绿边消除；一个运行帧中 alpha>32 的 415,380 个像素，绿色超出红/蓝通道超过 8 级的像素数为 0。固定示例连续完成两次，仍输出 41,600 samples / 2.6 秒，队列排空且返回就绪。检查时运行帧数已达 2,745，人物视频保持 0.65 倍速循环，WebGL 错误码为 0；42 项测试、类型检查、构建与资源完整性校验均通过。本轮未重新调用豆包，画面回归使用同一播放器的固定音频完成。


## 二次观感调整：固定身体和头部（2026-09-07）

用户认为前版仍有肩膀和脖子扭动。本次移除局部头部稳定变形及颈肩过渡着色器，直接使用显式解码的第 2 帧（从 0 计数，0.08 秒）的正面人物及对应姿态数据；底板视频保持暂停。25 fps 人脸推理与合成循环继续运行，不暂停音频或嘴型。保留嘴部合成后的去绿处理。

当前取舍：肩膀、衣服、头部轮廓和上半脸固定，仅模型驱动的嘴部及周围面部区域变化；底板自带眨眼一并停止。本次优先满足用户明确提出的稳定坐姿，不再用身体变形模拟自然动作。

验证记录：内置 Chromium 中覆盖一次固定音频播报的约 10 秒、49 次采样，与基准帧逐像素对比。排除嘴部推理矩形及 2 像素边界后，其他区域变化像素最大值为 0；推理矩形内部变化像素最大值为 23,649。底板时间保持 0.08 秒、paused=true，WASM 渲染帧继续增加，WebGL 错误码为 0，2.6 秒示例正常完成且队列排空。已通过 42 项测试、类型检查、构建和 12 项资源哈希校验；本轮未额外调用豆包。


## 最新调整：身体固定，恢复眨眼和轻微头部活动（2026-09-07）

用户澄清头部与面部可以轻微活动，要求尽量固定头部以下。本节替代上节的全静止底板方案。

以 0.08 秒已解码画面为固定身体底板。上层恢复人物视频中的眨眼和面部运动，视频速度为 0.75；对已合成嘴型的整块头部做刚性平移/旋转补偿，保留 15% 原平移和侧倾幅度（素材侧倾总范围目标约 1.92°）。不再局部拉扯颈肩。头部层在原画布 y=566 至 606 的窄颈部区域渐隐，y≥606 使用固定身体，最后统一去绿。嘴型推理和语音播放速度不变。

头部的三维转向仍来自原素材，此二维处理主要限制平移和侧倾；颈部连接区允许小幅变化，肩膀及身体保持固定。眨眼来自原素材，而非新增随机眨眼动画。

验证：内置 Chromium 约 21 秒、52 次采样，覆盖 14.32 秒素材在 0.75 倍速下的完整循环。固定身体区（y≥608，含 2 像素边界余量）的变化像素最大值为 0，头部区域持续变化；固定音频正常播完、队列排空、WebGL 错误码 0。42 项测试、类型检查、构建与资源校验均通过。本轮未额外调用豆包。


## 最新修正：仅脸部内部变化，颈部完全固定（2026-09-07）

用户明确否定颈部运动及断层。本节替代此前的头部/身体分层方案；此前只检查 y≥608 的身体区未覆盖颈部接缝，验收范围不充分。

移除整个移动头层、刚性头部补偿和颈部渐隐接缝，底板固定在第 2 帧。WASM 嘴型仍使用相同基准帧和姿态，但结果只通过脸内部的柔边椭圆显示，范围为中心 (350,451)、半径 (78,68)，不修改下巴轮廓与颈部。闭眼使用同一素材经目视核实的第 65 帧，按素材姿态对齐到基准脸，只保留中心 (294,354)、(398,354)、半径 (34,21) 的两块柔边眼睑。其余闭眼帧像素完全丢弃。每约 4.7 秒进行一次约 270 ms 的局部开闭眼混合；这属于局部贴片眨眼，不是持续播放原视频，也不承诺通用照片适配。

保留最终去绿及现有音频链路，不再声称整块头部活动属于面部表情。区域坐标只针对当前 720×1080 的固定人物资产。

原 WASM 生成的 MatesX 标识从首次中性渲染复制到固定底板，未通过局部面部遮罩移除；标识与颈部一起保持静止。

最终版本验证：约 12 秒、77 次像素采样，覆盖眨眼和示例播报。三个脸内部动画椭圆及 2 像素采样余量之外，变化像素最大值为 0；整个 y≥525 的颈部及下方区域变化像素最大值为 0。眼部变化最大 4,318 像素，嘴周变化最大 12,766 像素，确认两种动作均发生。原标识保留，示例 2.6 秒正常完成且队列排空，WebGL 错误码 0。42 项测试通过，最终构建和 12 项资源哈希复核通过；本轮没有新增豆包调用。
