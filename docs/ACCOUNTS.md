# 账户、管理员与人物授权

2026-09-11，用户批准账户方案 v3。本阶段为本地单实例；多个账号可以同时登录，全系统同时一场通话，管理员测试也不抢占。

## 使用

打开 `http://127.0.0.1:5173/` 登录。管理员账号 `lenox` 已在本次本机数据库初始化，使用用户指定的初始测试密码。代码、PRD、日志不保存明文密码。管理员登录进入用户管理，也可切换人物管理和管理员账户。

1. 管理员点击“创建用户”，填写唯一账号。密码留空会随机生成12位，也可手动填写12—128位。新密码仅在创建/重置结果中显示一次，由管理员自行交付给对应用户；关闭后不能查询旧密码。
2. 选择用户，勾选一个或多个人物进行分配。账号不限制人物总数；单次请求最多500个人物是请求大小防护，可分批添加。
3. 点击“专属设定”，设置这个用户看到的人物名、关系称呼、提示词和背景。首次分配复制当时默认设定，以后与共享人物、其他用户独立；修改仅在下一场通话使用。解绑后重新授权保留此前该用户的设定。
4. 普通用户登录只看到已分配人物。没有授权时联系管理员；人物制作未完成时暂不能呼叫。普通用户不能注册、创建/编辑人物、改密、自助找回或进入管理接口。
5. 重置密码、停用账号会撤销该账号全部旧登录并结束依赖的通话。取消一个人物授权仅影响目标用户与目标人物，其他用户和其他授权不受影响。普通退出只撤销当前登录。

共享人物软删除沿用已有规则：先结束其通话再删除，资料保留，所有用户均无法继续访问。默认人物修改不会覆盖已经分配的用户设定。

## 初始化与管理员恢复

新环境使用 `npm run account:init`。通过进程环境安全注入 `ADMIN_INITIAL_PASSWORD`，或从不回显的标准输入提供一行密码。不要把真实密码写入命令示例、脚本或仓库文件。该命令发现管理员已存在时不覆盖密码。

通用初始化要求至少12位。仅为兼容本次用户明确指定的较短初始测试密码，`npm run account:init -- --local-test-initial` 可在非 production 环境允许10位；这是显式本地例外。服务启动也可用 `ADMIN_INITIAL_PASSWORD` 完成首次初始化；较短测试密码额外要求非 production 且 `AUTH_ALLOW_LOCAL_TEST_PASSWORD=1`。初始化后删除进程内该环境值，不在重启时重设密码。

已登录管理员在“管理员账户”验证旧密码后设置新密码。忘记管理员密码时，服务器拥有者可执行 `npm run account:reset`，通过受控标准输入或同名初始化环境变量传入新的至少12位密码。运维重置撤销旧登录；运行中的网关每秒复核并关闭失效连接。恢复命令不对外提供HTTP接口，也不会清空其他账户、人物或设定。

## 实现与边界

- 复用 `artifacts/avatars/avatars.sqlite`；`users` 保存唯一账号、角色、状态、密码哈希及认证版本；`auth_sessions` 保存令牌哈希和期限；`user_avatars` 按 `(user_id, avatar_id)` 唯一保存独立配置；`account_audit` 只记录管理事件和目标，不记录密码或提示词。
- 密码使用带随机盐的 scrypt，参数 N=131072、r=8、p=1。并行密码运算最多2项，限制内存占用；登录按账号和来源频控。
- 随机服务端会话通过 HttpOnly、SameSite=Strict Cookie 使用，不写浏览器 localStorage。`AUTH_ADMIN_SECONDS` 默认28800，`AUTH_USER_SECONDS` 默认604800；`AUTH_SECURE_COOKIE=1` 仅供HTTPS环境，本阶段使用本机HTTP。到期会使实时连接失效，而不只检查下一次网页请求。
- 敏感请求同时检查可信来源和自定义请求头。HTTP、HEAD、Range以及WS均检查身份与人物授权；实时收发和准备阶段复核身份。关闭上游连接后才释放全局通话位。
- Vite只允许必要源目录，拒绝私有目录、SQLite、备份、密钥和环境文件；存储目录不得位于 `apps/web` 内，包括 `public`。此防护不等于已经完成公网部署。
- 上传在授权过期或失败时删除本次尚未登记的文件。清理失败逐项记录在 `uncommitted_uploads`，不导入为历史人物，重启时重试。不会把用户原始文件或已提交人物作为清理目标。
- 旧匿名网关诊断脚本现在需要 `DIAGNOSTIC_USERNAME` / `DIAGNOSTIC_PASSWORD` 进程环境；可选 `DIAGNOSTIC_AVATAR_ID`。会话票据不写报告。这些真实供应商诊断仍需要明确同意付费调用，本轮未执行。

## 备份与恢复

账户迁移前使用SQLite在线备份，包含WAL中的数据。自动备份位于同一私有目录下的 `before-accounts-*.sqlite` 或运维命令生成的 `account-backup-*.sqlite`。这些文件含私有资料与密码哈希，应与正式数据库同等保护，不纳入Git。

完整迁移机器前应停止服务，备份整个 `artifacts/avatars`，包括媒体；仅同步Git不会同步账户、照片和人物。恢复数据库前停止服务并保留当前目录备份，使用成套备份，避免将旧数据库与仍在运行的WAL混用。恢复较旧账户数据库会恢复当时的密码和会话状态，恢复后应进行管理员密码重置并撤销普通用户旧会话。

## 验证

自动测试包括账户持久化、密码哈希、初始化幂等、独立设定、授权复用、重置停用撤销、CSRF/频控、HTTP/HEAD/Range/WS隔离、准备期间撤权、单通话竞争、到期关闭、WAL备份、静态目录拒绝及撤销上传清理失败恢复。

`scripts/verify-accounts-browser.ts` 使用临时数据库和本地模拟语音服务，两个独立Chrome上下文验证管理与用户流程，输出脱敏结果和桌面/手机截图至 `artifacts/account-verification`。通过 `PLAYWRIGHT_MODULE` 与 `CHROME_EXECUTABLE` 指定本机已安装运行时。它不读取真实人物资料、不调用付费模型、不依赖真人麦克风。

相关命令：`npm test`、`npm run build`、`npm run avatar:verify`、`git diff --check`。公网HTTPS、多人同时通话和真人音视频质量不属于本轮新增验收承诺。
