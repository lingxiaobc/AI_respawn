# 角色管理、照片规范化与接听入口

2026-09-09 用户批准，并在实际图片对比后修正：每张新照片仍经 ZenMux，目的是规范人物取景、支持嘴部资源制作，不是重画人像。

## 使用流程

每批上传 1—3 张照片 → 主图片模型编辑 → 主模型失败时备用模型尝试一次 → 人物可用性检查 → 本地制作 → 人物列表 → 点击视频通话 → 绿色接听 → 豆包语音与本地嘴型。

全程自动，不增加每张图片的确认步骤。原有成品角色不会自动重新生图。用户上传副本保留，电脑中选择的原文件不修改。标准图、原图和本地制作尝试分开存放。

照片提示词要求：保留原有笑容、露齿、自然姿势及亲和感；保留眼耳口鼻、五官比例、轮廓、自然不对称、年龄、皱纹、肤色与皮肤细节。不强制闭嘴、严格转正或证件照化，不美颜、年轻化、换背景。人物较远时调整取景和占比，已有合格近景尽量不改。模型输出无法从技术上保证逐像素或所有照片的身份一致性；单脸检测不等于保真验收。

## 角色管理

- 重命名：1—100 个字符，完整显示保存的名称，包括点号。
- 角色设定：最多 2000 个字符，可填写与用户的关系、性格、语气、说话方式和背景；服务端读取，在每次新通话创建时形成独立快照。默认声音及半双工方式不变，不加入跨场记忆。
- 删除：数据库 `DELET_OR_NOT` 为 `false/0` 时可见，`true/1` 时归档，另记删除时间。原图、标准图和资源仍保留；列表、资源读取、通话和重试入口排除已归档角色。后台任务停止，晚到结果不能使角色复活。正在通话的角色先挂断再删除。本轮不提供物理清理和恢复入口。

## 接听与后台任务

进入人物页面仅展示静态照片及接听按钮，不创建 WebSocket、麦克风、动态 iframe、通话计时或制作抢占。点击接听后才正式启动，重复点击不会并行建会话；等待时返回不影响后台制作。

通话优先于本地制作和图片校验，确认本地进程退出后接通。已经提交的云端生图允许返回并保存；通话期间不继续校验、制作或派发回退请求。挂断后继续。意外重启不自动重放结果不明的付费请求，需要用户手动重试。

已成功保存的标准图用于后续重试，本地制作失败或通话打断不会重复生成。主模型错误、超时、无有效图片或人物检查不通过可回退一次；两者失败显示单张失败，其他继续。校验环境不可用属于本地故障，保留收到的图并提示修复环境，不白白调用备用模型。主模型超时可能已经计费，回退可能产生第二笔用量。

## 配置与存储

服务端读取 `.env` 中 `ZENMUX_API_KEY`、`IMAGE_MODEL_ID`、`ROLLBACK_MODEL`。当前主模型使用 OpenAI Images 编辑接口，Google 回退模型使用 Gemini/Vertex `generateContent`；两个接口都提交原始照片和同一保真提示词。密钥不进入浏览器、Python 工作进程、数据库或日志。

照片会发送至 ZenMux 及其上游模型；豆包只负责现有语音链路。SQLite 保存角色、归档标志、设定和规范化检查点；媒体文件留在本机 `artifacts/avatars/<id>/`。软删除不等同本地或供应商内容清除。通话运行明细仍按已有 30 天策略处理。

官方接口：[Images 编辑](https://zenmux.ai/docs/api/openai/create-image-edit.html)、[Vertex Generate Content](https://zenmux.ai/docs/api/vertexai/generate-content.html)。
