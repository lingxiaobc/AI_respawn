# Live2D Local Toolchain Setup

The art package is ready, but the official Live2D tools require a person to review and accept Live2D's agreements. This project does not record an email address or automate consent.

## Required downloads

1. Cubism Editor for Windows, stable release:
   `https://www.live2d.com/en/cubism/download/editor/`
2. Cubism SDK for Web, stable release:
   `https://www.live2d.com/en/sdk/download/web/`

On both pages, choose the appropriate individual/enterprise option, enter an email address if required, review the terms, and explicitly consent. Downloading or launching the software constitutes acceptance under Live2D's page notice.

## Install and place files

1. Install Cubism Editor in its default Windows location.
2. Extract the Cubism SDK for Web package outside the repository or under a user-approved local tools directory.
3. Do not commit the proprietary Cubism Core unless its license explicitly permits the intended distribution.
4. Confirm these are available:
   - Cubism Editor executable.
   - `Core/live2dcubismcore.js` and its TypeScript declaration.
   - Cubism Web Framework and TypeScript sample.

## Resume point

Open the already verified final source model:

```text
AI_output/live2d/model/portrait_cubism_runtime_ready.cmo3
```

The PSD import, full opaque base, three parameter bindings, combined-state checks, save, close, reopen, and persistence checks are complete. Do not repeat the superseded PSD import routes unless the final source model is proven corrupt. The intended parameter-to-layer mapping remains documented in `AI_output/live2d/model/LAYER_MAP.md`.

Before Web integration, export into `AI_output/live2d/runtime/portrait/`:

```text
portrait.moc3
portrait.model3.json
portrait.cdi3.json
portrait.<atlas-size>/texture_00.png
portrait.<atlas-size>/texture_01.png  (only when Cubism generates more than one texture)
```

In Cubism Editor 5.3:

1. With `portrait_cubism_runtime_ready.cmo3` open, create or inspect the texture atlas and make sure every required ArtMesh is placed.
2. Use `File -> Export Embedded File -> Export as MOC3 file` (`Ctrl+Alt+S`).
3. Select the current Cubism 5 SDK export version, SDK export type, and texture target `1/1`.
4. Export all required model ArtMeshes, do not export guide images, and enable the display information file (`cdi3.json`). Physics, motion-sync, user-data, and motion files are not required for this three-parameter Stage 0.
5. Use the base name `portrait` and the directory above. Keep every texture file and directory name generated by Cubism; do not force the atlas size or texture count shown in the example. Do not overwrite the `.cmo3` source model.

After export, verify the generated `portrait.model3.json` references the generated `.moc3` and texture using relative paths. Then load the model in Cubism Viewer and the official Cubism Web sample before modifying the application.

## Current status

Cubism Editor 5.3.03 FREE and Cubism SDK for Web 5-r.5 are available under `P:\live2D`. The final source model and runtime export are complete. The official SDK TypeScript Demo has loaded and rendered the default model, individual eye closures, both eyes closed, mouth open, and the combined mouth-open/eyes-closed state without final console errors or warnings.

The React application now loads the exported model through an isolated Canvas adapter. `apps/web/vite.config.ts` serves the local SDK Core, Framework shaders, and model assets in development and copies the required runtime files into the production build. The SDK remains outside the repository. If it is installed elsewhere, set `LIVE2D_SDK_PATH` before running `npm run dev:web` or `npm run build`.

Use `http://127.0.0.1:5173/?live2dDebug=1` during development to expose the fixed one-second mouth diagnostic. The diagnostic routes generated PCM through the same `AudioBufferSourceNode -> AnalyserNode -> destination` chain as provider audio; it is removed from production builds. Normal runtime behavior uses non-fixed 200 ms blinks and maps only actual playback amplitude to `ParamMouthOpenY`.
