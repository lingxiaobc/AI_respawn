## 2. 产品定义

### 2.1 一句话定义

管理员用一张真人照片、一段获授权的参考音频以及昵称和性格配置创建角色；系统生成并保存可复用的轻度可动 2D 人像和克隆音色。管理员审核发布后，获授权用户可以在手机网页中只用麦克风与该角色进行半双工实时语音通话，AI 回复音频实时驱动人像嘴巴张合，眼皮偶尔自然眨动。

### 2.2 产品不是“预先生成一段视频”

“生成角色”指生成可供实时通话反复使用的角色资产，不是生成固定时长的视频文件。每次通话时：

1. 用户语音实时发送给豆包实时语音服务；
2. 豆包实时返回 AI 回复音频；
3. 浏览器边播放回复音频，边分析该回复音频的音量；
4. 输出音量映射为嘴巴张开幅度；
5. 眼皮由本地随机眨眼控制器驱动；
6. 除嘴部和眼皮局部区域外，管理员批准的规范图在所有运行帧中保持不变。

用户不上传摄像头画面，系统也不根据用户表情、姿态或环境做视觉反馈。

### 2.3 核心价值

- 管理员用较少人工操作把照片和声音转化为可重复使用的实时角色。
- 多个用户可以访问同一个角色，避免重复生成相同视觉和音色资产。
- 共享角色的同时，严格隔离每个用户与该角色的会话记录和记忆。
- 以“能自然开合嘴、偶尔眨眼、其余画面稳定”为核心效果，不为追求真人级视频增加不必要复杂度。

## 3. 产品目标与成功标准

### 3.1 MVP 目标

| ID | 目标 | 发布判断 |
| --- | --- | --- |
| OBJ-001 | 完成管理员端与用户端的身份和权限隔离 | 后端授权测试不存在跨角色、跨用户或越权访问 |
| OBJ-002 | 完成单照片到规范图与轻度可动资产的受控生成 | 不合格照片被拒绝；合格资产可预览并经管理员批准 |
| OBJ-003 | 完成参考音频到可调用克隆音色的受控流程 | 音色状态可追踪、可试听、失败可重传、批准后才发布 |
| OBJ-004 | 完成手机网页上的半双工实时通话 | 用户只授权麦克风即可完成连续的一问一答循环 |
| OBJ-005 | 达到明确的 2D 动画边界 | 嘴随 AI 输出音量变化、偶尔眨眼、其他像素在运行帧之间不变化 |
| OBJ-006 | 支持同一角色授权给多个用户并隔离记忆 | 角色资源共享；任何用户不能读取或影响其他用户的会话和记忆 |
| OBJ-007 | 支撑当前运营规模并保留容量证据 | 每日约 5 个角色的处理链可运营；上线前完成目标并发实测 |

### 3.2 首发效果标准

- 角色画面是正脸或接近正脸、五官完整清晰、自然放松、适合手机视频通话构图。
- 静音时嘴巴自然闭合，非严肃、非明显抿嘴，可以有非常轻微的微笑。
- 说话时嘴部只按 AI 输出音频音量改变张开大小，不要求不同音素对应不同口型。
- 眼皮偶尔自然闭合并重新睁开，不要求眼球跟踪、眉毛或复杂情绪。
- 不要求头部转动、身体动作、手势、全身画面或真人级视频质量。
- 角色回复必须是实时生成、流式播放；不得等完整音频或固定视频全部生成后才开始播放。

### 3.3 产品指标

| ID | 指标 | MVP 门槛 |
| --- | --- | --- |
| KPI-001 | 未授权角色访问成功数 | 必须为 0 |
| KPI-002 | 跨用户读取或串写记忆次数 | 必须为 0 |
| KPI-003 | 未经管理员批准即对用户可见的角色数 | 必须为 0 |
| KPI-004 | 规范图运行帧在嘴眼允许区域外的像素差异 | 确定性验收环境中必须为 0 |
| KPI-005 | AI 回复音频与嘴部动作方向一致性 | 有声时嘴部可动；静音后回到自然闭合；不得由用户麦克风驱动 |
| KPI-006 | 本地基线连续通话 | 延续当前工程 Gate：10 轮至少 9 轮成功、P95 判停到首声不高于 3 秒；正式移动端和公网环境需重新实测，不自动视为生产 SLA |
| KPI-007 | 角色处理量 | 支持当前约每日 5 个角色；峰值并发和成本上限见 TBD-001 |

## 4. 范围

### 4.1 MVP 范围内

- 管理员和用户的独立登录入口、会话与后端角色授权；
- 管理员创建、编辑、删除角色；
- 单张照片上传、质量检测、拒绝反馈、规范化、缺肩补全和预览审批；
- 单个参考音频上传、质量校验、音色复刻任务、状态查询、试听和审批；
- 角色昵称和性格配置；
- 角色生成异步任务、进度和失败重试入口；
- 角色发布、撤回、用户分配和取消分配；
- 用户查看获授权角色并发起视频通话；
- 豆包实时语音、半双工自动判停、流式播放；
- AI 输出音量驱动嘴部、随机自然眨眼；
- 用户与角色维度的会话和记忆隔离；
- 上传、审批、发布、授权、删除和关键失败的审计记录；
- 手机浏览器优先的响应式页面和麦克风权限处理；
- AI 生成/合成身份提示与上线合规闸门。

### 4.2 明确不在 MVP 范围

| ID | 非目标 | 原因 |
| --- | --- | --- |
| NG-001 | 用户摄像头、表情识别、姿态识别 | 客户只需要用户语音输入 |
| NG-002 | 用户打断 AI、全双工同时说话 | MVP 采用半双工一问一答 |
| NG-003 | 头部转动、眼球跟踪、身体或手势动作 | 不贡献当前核心效果且显著增加资产复杂度 |
| NG-004 | 复杂情绪和面部表情系统 | 只要求嘴巴和眼皮轻度可动 |
| NG-005 | 音素级口型或唇音同步 | 嘴部只按音量张合 |
| NG-006 | 背景音乐、多人声或多人同一通话 | 首版只有用户与一个角色对话 |
| NG-007 | 知识库或 RAG | 性格和上下文由管理员配置及实时 API 承载 |
| NG-008 | 真人级神经视频生成 | 产品目标是轻度可动 2D 照片 |
| NG-009 | 固定时长的预生成通话视频 | 通话时长由实时对话决定 |
| NG-010 | 强制采用 Live2D | 客户只约束效果，不约束具体技术 |
| NG-011 | 原生 iOS/Android 应用 | 首发为手机网页应用 |
| NG-012 | 多租户企业组织和复杂运营后台 | 当前为单管理员、小规模运营 |

任何非目标进入开发前，都必须升级 PRD 版本并获得产品负责人明确批准。

## 5. 用户角色与权限

### 5.1 角色定义

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 管理员 | 当前预计为产品负责人本人 | 管理用户、创建和删除角色、上传素材、编辑性格、查看任务状态、试听预览、批准发布、分配角色、撤回授权 |
| 用户 | 被管理员创建或邀请的最终使用者 | 登录、查看本人获授权且已发布的角色、发起和结束通话、管理本人麦克风权限、使用本人会话与记忆 |
| 系统任务 | 后台异步处理身份，不是可登录人员 | 仅按任务最小权限读取指定输入、写入指定产物与状态 |

| 资源/操作 | 管理员 | 用户 | 系统任务 |

| 原始照片和音频上传 | 允许 | 禁止 | 只读指定任务输入 |
| 规范图和音色预览、批准 | 允许 | 禁止 | 生成或更新状态，不得批准 |
| 角色发布、撤回 | 允许 | 禁止 | 禁止 |
| 用户角色分配 | 允许 | 禁止 | 禁止 |
| 已授权角色列表 | 可查看全部 | 仅本人 | 禁止 |
| 发起角色通话 | 可在预览模式测试 | 仅本人已授权且已发布角色 | 禁止 |
| 用户会话和记忆 | 默认不展示正文；可按授权执行删除 | 仅本人 | 仅在当前用户与角色范围内读写 |
| 审计记录 | 允许查看必要元数据 | 禁止 | 只追加必要事件 |

### 5.3 强制权限规则

- FR-AUTH-001：管理员与用户必须使用相互隔离的登录入口或明确的角色路由。
- FR-AUTH-002：权限必须由服务器端校验；前端隐藏按钮不能作为权限控制。
- FR-AUTH-003：每个请求必须绑定已认证主体；禁止只凭可猜测 URL、角色 ID 或前端参数访问资源。
- FR-AUTH-004：用户只能访问同时满足“角色已发布”和“有效分配关系存在”的角色。
- FR-AUTH-005：管理员会话和用户会话必须有独立的授权范围；普通用户令牌不得调用管理员接口。
- FR-AUTH-006：账号被禁用、分配被撤回或角色被撤回后，新请求必须立即失去访问权；已建立通话如何终止见 TBD-006。

## 7. 端到端用户流程

### 7.1 管理员创建并发布角色

```text
管理员登录
  → 新建角色草稿
  → 输入昵称与性格
  → 上传一张照片和一段参考音频
  → 系统分别校验图片和音频
      → 不合格：说明原因并要求重传
      → 合格：创建异步处理任务
  → 图片规范化/补全并生成嘴眼资产
  → 申请或选择 speaker ID，上传音频并查询复刻状态
  → 图片和音色均进入待审核
  → 管理员预览画面、嘴眼动作并试听音色
      → 驳回：回到相应素材或处理步骤
      → 批准：锁定规范图和已批准音色版本
  → 系统检查发布条件
  → 管理员发布角色
```

成功结果：角色进入 `PUBLISHED`，但只有被管理员分配的用户能够看到。

失败去向：失败必须落到图片、音色、人格配置、异步任务或发布条件中的明确子状态，不得只显示“生成失败”。

### 7.2 管理员向多个用户分配同一角色

```text
管理员选择已发布角色
  → 选择一个或多个有效用户
  → 创建用户-角色分配关系
  → 用户下次刷新列表后可见
```

每个分配关系相互独立。撤回用户 A 的授权，不得影响用户 B，也不得删除共享角色资产。

### 7.3 用户发起并完成一轮通话

```text
用户登录
  → 打开“我的角色”
  → 选择已授权角色
  → 点击“视频通话”
  → 页面验证发布状态和授权
  → 申请麦克风权限，不申请摄像头权限
  → 建立实时会话并进入 listening
  → 用户说话
  → 自动检测有效讲话与句末静音
  → 提交用户轮次，进入 thinking
  → AI 返回流式语音，进入 speaking
  → 浏览器播放语音并用输出音量驱动嘴部
  → 回复完成、嘴巴闭合，回到 listening
  → 用户结束或会话异常关闭
```

成功结果：同一页面内可连续完成多轮一问一答，当前用户与当前角色的会话上下文按隔离键保存。

失败去向：麦克风拒绝、网络中断、供应商错误、授权失效和音频播放失败必须显示不同的可行动提示。

### 7.4 管理员删除角色

```text
管理员发起删除
  → 页面展示受影响的共享用户、资产和记忆范围
  → 管理员确认
  → 角色立即停止新通话并从用户列表隐藏
  → 后台按删除策略处理资产、分配关系和关联记忆
  → 记录审计结果
```

删除是否提供宽限期、是否立即终止进行中的通话、备份保留期见 TBD-004 至 TBD-006；在这些问题确定前，不得宣称物理数据已立即不可恢复。

## 8. 生命周期与状态机

### 8.1 角色总体状态

| 状态 | 含义 | 允许进入方式 | 用户是否可见 |
| --- | --- | --- | --- |
| `DRAFT` | 草稿，可编辑，尚未提交处理 | 管理员新建 | 否 |
| `PROCESSING` | 至少一个必要子任务正在排队或处理 | 管理员提交生成或重试 | 否 |
| `ACTION_REQUIRED` | 输入不合格或任务失败，需要管理员处理 | 校验或异步任务失败 | 否 |
| `REVIEW_REQUIRED` | 必要资产均已产生，等待管理员审核 | 图片、音色和性格均达到可审核状态 | 否 |
| `APPROVED` | 资产已被管理员批准但尚未发布 | 管理员完成全部批准 | 否 |
| `PUBLISHED` | 可被分配并供已授权用户通话 | 管理员发布且发布门槛全部通过 | 是，仅授权用户 |
| `WITHDRAWN` | 已撤回，保留资产但禁止用户通话 | 管理员撤回 | 否 |
| `DELETING` | 删除处理中，禁止新访问 | 管理员确认删除 | 否 |
| `DELETED` | 产品逻辑删除完成 | 删除任务成功 | 否 |

禁止的状态跳跃：`DRAFT/PROCESSING/ACTION_REQUIRED/REVIEW_REQUIRED` 不得直接进入 `PUBLISHED`；系统任务不得把任何状态直接改为 `APPROVED` 或 `PUBLISHED`。

### 8.2 图片子状态

```text
NOT_UPLOADED
  → VALIDATING
      → REJECTED_INPUT → VALIDATING（重传）
      → QUEUED → PROCESSING
          → FAILED → QUEUED（管理员重试或重传）
          → REVIEW_REQUIRED
              → REJECTED_OUTPUT → QUEUED 或 VALIDATING
              → APPROVED
```

图片重新上传或重新生成后，旧的图片批准自动失效。已发布角色修改规范图时必须先生成新版本并重新审核；旧版本是否继续服务由发布策略决定，禁止未审核热替换。

### 8.3 音色子状态

```text
NOT_UPLOADED
  → VALIDATING
      → REJECTED_INPUT → VALIDATING（重传）
      → SPEAKER_ID_READY
      → UPLOADING → TRAINING
          → FAILED → SPEAKER_ID_READY 或 VALIDATING
          → PREVIEW_READY
              → REJECTED_OUTPUT → SPEAKER_ID_READY 或 VALIDATING
              → APPROVED
```

系统必须保存当前供应商、模型类型、speaker ID、训练状态、版本/次数、有效期信息和管理员批准的版本。不得假设“上传完成后供应商一定返回一个全新的音色 ID”；具体流程以选定计费模式和当前官方接口为准。

### 8.4 用户角色分配状态

| 状态 | 含义 |
| --- | --- |
| `ACTIVE` | 用户可在角色已发布时访问 |
| `REVOKED` | 用户不可再发起新访问，保留审计记录 |

唯一有效关系由 `user_id + character_id` 确定，重复分配必须幂等。

### 8.5 实时通话状态

```text
IDLE
  → AUTHORIZING
  → INITIALIZING
  → LISTENING
  → COMMITTING
  → THINKING
  → SPEAKING
  → LISTENING

任意活动状态 → ERROR → ENDED
任意活动状态 → ENDING → ENDED
```

- `LISTENING`：只处理用户麦克风输入和本地判停。
- `THINKING`：用户输入已提交，等待 AI 首个输出。
- `SPEAKING`：播放 AI 输出；MVP 禁止用户在此状态打断或开启新一轮。
- 播放完成后嘴巴必须回到自然闭合，再重新进入 `LISTENING`。

## 9. 功能需求

### 9.1 账号、登录与用户管理

- FR-ACC-001：系统必须提供管理员登录和用户登录，并在页面、路由、令牌权限和服务器接口四层保持角色隔离。
- FR-ACC-002：登录失败必须使用不泄露账号是否存在的通用错误提示，并记录脱敏安全事件。
- FR-ACC-003：管理员必须能够创建、禁用和删除用户账号；具体登录方式见 TBD-002。
- FR-ACC-004：被禁用用户不得建立新会话或刷新访问令牌。
- FR-ACC-005：用户端不得显示管理入口，管理员接口也不得接受用户凭据。

### 9.2 角色管理

- FR-CHAR-001：管理员必须能够创建角色草稿，并填写唯一内部名称、展示昵称和性格配置。
- FR-CHAR-002：昵称和性格配置必须版本化；修改已发布角色时不得静默覆盖正在使用的已批准版本。
- FR-CHAR-003：管理员必须能够查看角色各子任务的独立状态、时间、失败原因和诊断 ID。
- FR-CHAR-004：系统必须以明确的发布条件计算角色是否可审核、可批准和可发布。
- FR-CHAR-005：管理员必须能够撤回角色；撤回后用户列表不再展示且不能发起新通话。
- FR-CHAR-006：管理员必须能够删除角色，删除前显示影响范围并二次确认。

### 9.3 图片上传与输入校验

- FR-IMG-001：每个角色当前版本只接受一张输入照片；宽高比可以是横图或竖图。
- FR-IMG-002：系统必须检测单人、脸部大小、近正脸、清晰度、五官完整、眼睛和嘴巴可见、严重遮挡和图片可解码性。
- FR-IMG-003：侧脸、多人、五官缺失、眼睛或嘴巴被遮挡、关键区域模糊、无可用人脸的图片必须拒绝；自然轻微张嘴、微笑或露齿不能单独构成拒绝理由，只要嘴部结构清晰并可规范化。
- FR-IMG-004：照片没有肩膀但五官完整时可以接受，并进入需要补肩的规范化路径。
- FR-IMG-005：拒绝结果必须说明可行动原因，例如“嘴部被遮挡，请上传正脸清晰照片”，不得只显示“上传失败”。
- FR-IMG-006：输入校验必须在创建昂贵生成任务之前完成；明显不合格输入不得继续消耗生成资源。
- FR-IMG-007：管理员必须确认其拥有或已取得处理该照片的授权；没有有效授权记录不得提交处理。

### 9.4 图片规范化与轻度可动资产

- FR-VIS-001：规范化输出必须以人物正脸和五官为中心，适配手机视频通话主要视区，不要求固定横竖比例。
- FR-VIS-002：原图包含可用肩膀时应该保留原有构图；缺肩时可以补充自然肩部、衣服和背景延展。
- FR-VIS-003：规范化应该最大程度保留原人物身份、面部特征、衣服、光线和背景，不得无目的重绘整张照片。
- FR-VIS-004：管理员批准后的规范图必须生成不可变版本标识和校验摘要，成为运行时唯一像素基准。
- FR-VIS-005：运行时只允许嘴部和左右眼皮批准区域发生变化；其他区域必须直接复用规范图，不得由生成模型逐帧重绘。
- FR-VIS-006：系统必须保存嘴部和左右眼皮的允许变化遮罩，遮罩之外的运行帧像素必须保持不变。
- FR-VIS-007：管理员必须能预览静音、不同嘴部张开幅度、闭眼和嘴眼组合状态。
- FR-VIS-008：管理员驳回规范图或动画资产时必须选择或填写原因，并可重新生成或重新上传。

### 9.5 音色复刻

- FR-VOICE-001：管理员必须能为角色上传一个参考音频文件并查看当前录音要求。
- FR-VOICE-002：录音要求必须跟随实际选定的豆包复刻模型和当前官方文档配置，不得把所有模型写死为同一时长。当前官方通用指导强调清晰、单人、低噪声、单轨、情绪稳定和 WAV；部分当前模型建议 10–15 秒，声音复刻 2.0 的最佳实践可能采用不同长度，接入时必须再次核对。
- FR-VOICE-003：系统必须在上传后检查文件可解码性、时长、声道、采样率、静音比例、削波、信噪情况和多人声风险；不满足当前模型配置时拒绝并说明原因。
- FR-VOICE-004：系统必须按供应商当前流程申请、选择或获取可用 speaker ID，再提交训练并轮询或接收训练状态。
- FR-VOICE-005：系统必须保存 speaker ID、供应商项目、模型类型、训练状态、训练版本/次数、有效期和最近错误；密钥不得保存在浏览器或角色记录中。
- FR-VOICE-006：训练成功后必须提供管理员试听；管理员批准前，音色不得进入用户实时通话。
- FR-VOICE-007：训练失败、音质不佳或管理员驳回时，必须允许重新上传；若供应商训练次数或计费模式限制继续训练，必须明确提示而不是无限重试。
- FR-VOICE-008：若选择的计费模式存在“首次正式合成后锁定”“试听有效期”或“启用后不可再训练”等规则，产品必须在不可逆操作前向管理员确认。
- FR-VOICE-009：系统必须把供应商返回的错误码、请求/日志 ID 和当前阶段保存为脱敏诊断信息，不保存或展示供应商密钥。

### 9.6 性格配置

- FR-PERS-001：管理员必须能输入角色性格、说话方式和必要边界提示。
- FR-PERS-002：性格配置作为角色共享资源版本化，同一已发布版本对所有获授权用户一致。
- FR-PERS-003：人格文本更新后必须经过管理员预览或确认，避免未审核提示直接影响在线角色。
- FR-PERS-004：MVP 不建设知识库；不得把缺少知识库视为实现缺陷。

### 9.7 异步生成任务

- FR-JOB-001：图片处理和音色复刻必须是独立可追踪的异步任务，不要求管理员停留在页面等待。
- FR-JOB-002：每个任务必须具有排队、处理中、成功、失败、取消等明确状态及创建/更新时间。
- FR-JOB-003：页面必须显示分阶段进度或当前阶段，不得用一个永久旋转图标代表所有状态。
- FR-JOB-004：重复提交必须幂等，避免刷新页面或网络重试创建多份收费任务。
- FR-JOB-005：自动重试只适用于明确可恢复的瞬时错误，并设次数和退避上限；输入错误、授权错误、额度不足和不可逆限制禁止盲目重试。
- FR-JOB-006：任务失败不得删除原始输入和错误证据，直到管理员已处理或数据保存期到期。
- FR-JOB-007：图片和音色任务可以并行；角色审核和发布必须等待所有必要子任务成功。

### 9.8 审核、发布与授权

- FR-PUB-001：角色进入管理员审核前，必须具备可预览规范图、嘴眼资产、可试听音色和完整性格配置。
- FR-PUB-002：图片、动画、音色和性格必须分别记录批准状态、批准人、批准时间和批准版本。
- FR-PUB-003：只有管理员可以批准和发布；后台任务成功不等于批准。
- FR-PUB-004：发布必须进行原子条件检查；任一批准已失效、资产被删除或供应商音色不可用时发布失败。
- FR-PUB-005：管理员必须能把同一已发布角色分配给多个用户。
- FR-PUB-006：用户角色分配必须支持撤回且幂等，不得因一个用户撤回而修改共享角色资产。
- FR-PUB-007：角色撤回、删除或重新发布必须留下审计记录。

### 9.9 用户角色列表

- FR-LIB-001：用户登录后只看到本人具有有效分配关系且当前为 `PUBLISHED` 的角色。
- FR-LIB-002：列表必须展示角色昵称和批准后的规范图缩略图，不展示原始上传照片或内部任务信息。
- FR-LIB-003：点击“视频通话”前，服务器必须再次检查用户状态、分配状态、角色发布状态和资产可用性。
- FR-LIB-004：没有角色时页面必须显示明确空状态，不得暴露其他用户或未发布角色。

### 9.10 实时语音与视频通话

- FR-CALL-001：用户端只请求麦克风权限，禁止请求摄像头权限。
- FR-CALL-002：通话采用半双工自动判停；用户有效讲话后出现句末静音时自动提交，不提供按住说话作为主交互。
- FR-CALL-003：AI 思考和播放期间不得采集或提交新的用户轮次；MVP 不支持打断。
- FR-CALL-004：豆包回复音频必须流式转发并尽快播放，不等待整段回复结束。
- FR-CALL-005：嘴部驱动源必须是正在播放的 AI 输出音频，而不是用户麦克风、输入转写或文本长度。
- FR-CALL-006：嘴巴张开幅度必须随输出音量包络连续变化，并在静音和播放完成后平滑返回闭合。
- FR-CALL-007：嘴型不区分音素，不要求唇读准确性。
- FR-CALL-008：眼皮必须在本地以非固定节奏偶尔自然眨动；左右眼可以同步，MVP 不要求独立表情。
- FR-CALL-009：除嘴部和眼皮允许区域外，运行时画面必须保持管理员批准规范图的像素不变。
- FR-CALL-010：界面必须清晰显示正在连接、正在听、正在思考、正在说话、已静音、错误和已结束状态。
- FR-CALL-011：用户必须能主动结束通话；页面离开、网络断开或令牌失效时，服务器和浏览器必须释放麦克风、音频、渲染和供应商会话资源。
- FR-CALL-012：AI 身份提示必须在进入或通话界面中清晰可见，避免用户误认为正在与真人视频连线。

### 9.11 会话与记忆隔离

- FR-MEM-001：记忆最小隔离键必须包含 `user_id + character_id`；每次实时连接另有唯一 `conversation_id/session_id`。
- FR-MEM-002：角色规范图、动画资产、音色和基础性格可以共享；用户输入、转写、对话历史、摘要和长期记忆禁止跨用户共享。
- FR-MEM-003：服务端查询和写入记忆时必须从已认证主体生成 `user_id`，禁止信任浏览器自行提交的任意用户 ID。
- FR-MEM-004：用户 A 与角色 X 的对话不得出现在用户 B 与角色 X 的上下文中。
- FR-MEM-005：记忆写入失败不得污染其他用户或其他角色；可以降级为当前轮临时上下文，并明确记录失败。
- FR-MEM-006：管理员默认不浏览用户对话正文；若未来需要客服审阅，必须作为新的权限和合规范围重新批准。
- FR-MEM-007：会话和记忆保存期限、用户查阅/删除入口及管理员代删流程见 TBD-004，上线前必须确定。

### 9.12 删除、审计与通知

- FR-DEL-001：管理员必须能删除其管理的角色、输入素材和生成资产；删除前必须展示级联影响并二次确认。
- FR-DEL-002：角色删除必须至少覆盖角色记录、版本、分配关系、规范图、动画资产、参考音频、音色关联和按政策应删除的记忆。
- FR-DEL-003：若供应商支持删除或回收音色，系统必须发起并记录结果；若不支持立即删除，必须记录外部残留和预计到期时间。
- FR-DEL-004：删除流程必须区分逻辑不可见和物理清除完成，禁止在外部资产仍存在时显示“已彻底删除”。
- FR-AUD-001：上传、校验拒绝、生成、重试、批准、发布、撤回、分配、登录安全事件和删除必须记录审计元数据。
- FR-AUD-002：审计日志不得包含 API 密钥、完整原始音频、图片二进制、完整转写或模型回复正文。
- FR-NOT-001：任务完成、失败、等待管理员审核和音色即将失效必须在管理员端形成可见提醒；首版不强制短信或外部消息。

## 10. 人像与动画专项产品规格

### 10.1 输入照片通过条件

| 检查项 | 通过条件 | 不通过处理 |
| --- | --- | --- |
| 人数 | 只有一个主要人物 | 拒绝，要求单人照片 |
| 姿态 | 正脸或接近正脸，双眼和嘴部可识别 | 明显侧脸拒绝 |
| 五官 | 双眼、鼻、嘴完整可见 | 缺失或遮挡拒绝 |
| 清晰度 | 关键五官无明显运动模糊、失焦或严重压缩 | 拒绝并说明模糊部位 |
| 表情 | 自然、非极端表情；允许轻微张嘴、微笑或露齿，只要嘴部结构清晰 | 极端表情、明显抿嘴或嘴部结构不可恢复时要求重传；其余在规范化阶段生成自然闭嘴基准 |
| 肩膀 | 可以缺失 | 接受并标记为需要补全 |
| 背景/衣服 | 无固定风格要求，但应可自然延展 | 无法合理延展时进入人工审核或要求重传 |
| 比例 | 横图或竖图均可 | 不因比例单独拒绝 |

阈值由图像技术设计定义，但测试必须使用明确数值和样本集；产品页面必须输出人能理解的拒绝理由。

### 10.2 规范图合同

规范图是管理员批准后锁定的角色视觉基准，必须满足：

- 五官清晰并位于移动端主要可视区域；
- 表情自然放松，静音嘴巴闭合但不明显抿紧；
- 原图已有肩膀时尽量不改变；原图无肩膀时补出自然肩部和相容衣服；
- 延展区域与原背景在颜色、光线、透视和纹理上协调；
- 不随意改变身份、发型、肤色、衣服款式、配饰或背景关键物体；
- 保存不可变资源版本、宽高、色彩空间、内容摘要和批准记录；
- 所有后续嘴眼资产必须与该确切版本绑定。

### 10.3 像素不变合同

- “其余像素不变”的比较基准是管理员批准后的规范图，不是最初上传的原图。
- 每个动画帧的允许变化集合等于嘴部遮罩、左眼皮遮罩和右眼皮遮罩的并集。
- 在相同画布尺寸、色彩空间和渲染配置下，允许集合之外任意像素的 RGBA 值不得随嘴部或眨眼参数变化。
- 实现不得使用全画幅视频生成或逐帧人像重绘来满足 MVP，因为这无法保证该合同。
- 若候选渲染技术会对整张图施加颜色、抗锯齿、缩放或后处理变化，必须调整合成方式；不能通过放宽产品要求掩盖。

### 10.4 嘴部合同

- 输入：正在实际播放的 AI 输出音频幅度或能量包络。
- 输出：从自然闭合到最大批准张开状态之间的连续标量。
- 静音：输出必须回到闭合基准，不得停在半开状态。
- 变化：必须有必要的平滑，避免逐音频采样抖动；具体 attack/release 数值由技术方案调试。
- 不要求：音素识别、牙齿或舌头精确运动、唇读级同步、情绪口型。

### 10.5 眨眼合同

- 眨眼在本地生成，不依赖用户视频或用户表情。
- 间隔不能表现为明显机械固定循环；确切随机范围由视觉验收调试。
- 一次眨眼包含闭合和重新睁开，不得长期停留在半闭状态。
- 嘴部与眼皮可以同时动作，组合状态不得破坏脸部或改变其他区域。

### 10.6 管理员视觉审核

管理员审核页至少提供：

- 规范图静态预览；
- 原图与规范图并排或可切换比较；
- 嘴巴闭合、小、中、大四个检查状态；
- 双眼睁开、闭合和一次自然眨眼；
- 嘴部动作与眨眼同时发生的组合预览；
- 移动端典型窄屏预览，确认脸部和关键元素不被裁掉；
- 批准、驳回、重新生成和重新上传入口。

## 11. 音色与实时语音专项产品规格

### 11.1 参考音频录制指导

管理员上传页必须根据已选模型显示当前官方要求。产品默认文案至少强调：

- 单人、单轨、低噪声、声音清晰；
- 不含背景音乐、其他人说话、明显回声、爆音、吞音或截断；
- 说话情绪和音量相对稳定；
- 推荐使用当前模型官方建议的 WAV、单声道和时长范围；
- 中英混合目标应按官方建议在参考音频中覆盖相应语言；
- 参考音频只能在已取得本人或合法权利人授权时上传。

产品不得把“最低可接受时长”宣传为“稳定获得最佳效果”。不同模型文档出现差异时，以实际启用模型的最新官方接入要求和实测为准。

### 11.2 speaker ID 与训练流程

当前产品语义定义如下：

1. `speaker_id` 是供应商侧音色槽位或音色身份的引用；
2. 系统可能先查询、购买、申请或选择该 ID，再上传参考音频；
3. 上传成功不等于音色可用，必须等待供应商状态达到可试听状态；
4. 保存训练版本/次数和是否可继续训练；
5. 管理员批准的是特定 speaker ID 的特定训练版本和模型配置；
6. 实时会话只能使用当前已批准且仍有效的音色引用。

若供应商接口语义变化，适配层可以改变，但上述产品状态和管理员确认门槛不得消失。

### 11.3 音色审核

- 试听必须使用不含敏感信息的短句，并覆盖角色主要语言。
- 管理员可以重复试听，不得因页面刷新丢失当前审核状态。
- 管理员可选择“音色不相似”“噪声”“发音异常”“截断/吞音”“音色突变”或自定义原因驳回。
- 供应商模型存在小概率截断、吞音或音色突变时，产品应允许重新训练或更换音频，并保留失败历史。
- 任何可能使音色不可再训练或开始计费的操作，必须提前说明并二次确认。

### 11.4 半双工实时链路

MVP 延续当前已验证原则：

- 浏览器本地确认有效讲话后才建立或开始供应商轮次；
- 初始静音不得提交空轮次；
- 句末静音自动提交；当前本地基线约为 1.2 秒，正式移动端阈值需实测调优；
- AI 回复期间锁定用户轮次，不支持打断；
- 输出音频按到达顺序连续播放，不重叠、不变速、不出现明显尖刺；
- 音频播放链同时向嘴部分析器提供实际输出信号；
- 每次连接、轮次和错误都有脱敏诊断 ID。

## 12. 数据模型与隔离规则

### 12.1 核心实体

| 实体 | 关键字段 | 数据归属与说明 |
| --- | --- | --- |
| `User` | user_id、role、status、auth metadata | 账号主体；凭据使用安全哈希或外部身份系统 |
| `Character` | character_id、nickname、status、current_version | 共享角色容器 |
| `CharacterVersion` | version_id、persona_version、image_version、voice_version | 将一次批准和发布绑定到不可变组合 |
| `SourceImage` | source_image_id、storage_ref、consent_ref、validation | 管理员上传的原始照片，受限访问 |
| `CanonicalImage` | canonical_image_id、dimensions、checksum、approval | 管理员批准后的不可变视觉基准 |
| `AnimationAsset` | asset_id、canonical_image_id、mouth_mask、eye_masks、runtime_manifest | 只能绑定一个规范图版本 |
| `VoiceReference` | voice_reference_id、storage_ref、validation、consent_ref | 原始参考音频，受限访问 |
| `VoiceClone` | voice_clone_id、provider、speaker_id、model_type、state、version、expiry | 供应商音色映射，不保存密钥 |
| `PersonaVersion` | persona_version_id、prompt、approved_at | 共享性格配置 |
| `GenerationJob` | job_id、type、state、input_version、attempt、diagnostic_id | 图片和音色任务分别记录 |
| `CharacterAssignment` | user_id、character_id、status | 多对多授权，唯一键为 user_id + character_id |
| `Conversation` | conversation_id、user_id、character_id、version_id、state | 一次用户会话 |
| `Memory` | memory_id、user_id、character_id、content_ref、scope | 私有记忆，禁止只有 character_id 的共享查询 |
| `ConsentRecord` | consent_id、subject、asset_type、scope、proof_ref、status | 肖像/声音处理与使用授权证据 |
| `AuditEvent` | event_id、actor_id、action、resource_id、result、time | 只存必要元数据和脱敏诊断信息 |

### 12.2 共享与私有边界

```text
共享角色域
  Character
  CharacterVersion
  CanonicalImage
  AnimationAsset
  VoiceClone
  PersonaVersion

用户私有域
  CharacterAssignment
  Conversation
  Memory

隔离键
  authenticated user_id + character_id
```

- 所有用户私有查询必须同时带服务端确认的 `user_id` 和目标 `character_id`。
- 仅以 `character_id` 查询全部记忆属于禁止实现。
- 管理员对角色的编辑不得重写历史会话所绑定的版本；新会话使用当前发布版本。
- 原始照片、参考音频和授权证明不得通过公共静态 URL 暴露。

## 13. 异常处理与恢复

| ID | 场景 | 用户/管理员提示 | 系统动作 |
| --- | --- | --- | --- |
| ERR-001 | 图片不合格 | 展示具体部位与重传建议 | 不创建生成任务 |
| ERR-002 | 图片生成失败 | 展示阶段、可重试性和诊断 ID | 保留输入与失败记录；只对瞬时错误自动重试 |
| ERR-003 | 生成图身份或背景偏差 | 允许管理员驳回并选原因 | 新建版本，不覆盖已批准版本 |
| ERR-004 | 音频不满足模型要求 | 展示格式、时长或噪声问题 | 不提交供应商训练 |
| ERR-005 | 音色训练失败 | 展示可重传/额度/权限提示 | 保存 speaker ID 状态和供应商诊断信息 |
| ERR-006 | 音色试听不满意 | 允许重传或重训 | 批准状态保持未通过 |
| ERR-007 | 供应商额度或权限不足 | 明确管理员操作入口 | 禁止无限自动重试 |
| ERR-008 | 用户拒绝麦克风权限 | 说明如何开启权限 | 不请求摄像头，不创建活动上游轮次 |
| ERR-009 | 网络或实时服务中断 | 显示连接失败与重试/结束 | 关闭旧会话资源；重试创建新连接 |
| ERR-010 | AI 输出音频失败 | 显示回复失败 | 嘴巴闭合，禁止假装继续说话 |
| ERR-011 | 授权在通话前失效 | 显示角色暂不可用 | 不建立供应商会话 |
| ERR-012 | 记忆服务不可用 | 可继续当前会话但提示上下文可能不保存 | 只使用当前会话临时上下文，禁止串写其他用户 |
| ERR-013 | 删除部分失败 | 显示“删除处理中/部分失败” | 保持不可见，记录未清理资源并继续受控补偿 |

错误提示必须回答：发生了什么、影响哪一步、是否可重试、下一步做什么。禁止把所有异常合并为“生成失败”或“网络错误”。

## 14. 非功能需求

### 14.1 移动端体验

- NFR-MOB-001：首发以主流手机浏览器竖屏为第一验收场景，同时兼容横屏和桌面；不得假设参考图比例固定。
- NFR-MOB-002：关键人脸、嘴眼和通话状态不得被安全区、地址栏、键盘或底部手势区域遮挡。
- NFR-MOB-003：开始通话、麦克风授权和结束通话必须单手可达；不能依赖 hover。
- NFR-MOB-004：页面在旋转、切后台和恢复时必须正确处理音频与会话；不允许恢复后重复播放或重复提交。
- NFR-MOB-005：资源加载时应有进度或骨架状态；失败时可重试，不显示空白画布。
- NFR-MOB-006：窄屏不得裁掉五官；必要时优先保证脸部完整，再处理肩膀和背景显示范围。

### 14.2 性能与容量

- NFR-PERF-001：AI 输出必须流式播放，不等待完整回复。
- NFR-PERF-002：嘴部动画必须在本地由播放信号驱动，避免为每个音频分片请求服务器动画结果。
- NFR-PERF-003：角色资产应按不可变版本缓存，但权限检查和用户记忆不得被公共缓存错误复用。
- NFR-PERF-004：上线前必须在选定手机、移动网络和目标区域完成首屏、建连、判停到首声、连续轮次、CPU/内存和耗电测试。
- NFR-PERF-005：上线容量必须由 TBD-001 确认，并验证实时连接、供应商并发、对象存储、任务队列和数据库连接的共同上限。
- NFR-PERF-006：每日约 5 个角色是当前运营输入，不代表同时通话数为 5，也不得用它替代并发设计。

### 14.3 安全与隐私

- NFR-SEC-001：公网环境必须使用 TLS/WSS；供应商密钥只保存在服务器端密钥管理中，禁止进入浏览器包、日志或数据库普通字段。
- NFR-SEC-002：原图、参考音频、规范图、授权证明和记忆必须采用私有存储和短时授权访问。
- NFR-SEC-003：上传文件必须限制类型、大小和解码行为，并进行恶意文件与内容安全检查。
- NFR-SEC-004：所有管理写操作必须进行身份校验、角色校验、CSRF/重放防护和审计。
- NFR-SEC-005：数据传输和存储必须按敏感级别采取加密、访问控制和最小权限。
- NFR-SEC-006：开发、测试、日志和 fixture 禁止使用未经授权的真实照片、真实声音、完整对话或生产密钥。
- NFR-SEC-007：会话令牌不得出现在 URL；退出、禁用和过期后必须失效。
- NFR-SEC-008：定期验证不存在 IDOR、跨用户记忆读取、未发布角色访问和管理员接口越权。

### 14.4 合规与内容标识

- NFR-COM-001：照片、声音复刻和角色发布前必须有可审计的合法授权或其他适用处理依据；缺失时禁止处理或发布。
- NFR-COM-002：页面必须明确告知用户正在与 AI 生成/合成角色交互，不得设计成真人实时连线的误导性界面。
- NFR-COM-003：正式发布前必须评估显式和隐式生成合成内容标识要求，并按适用规则落实。
- NFR-COM-004：必须提供投诉、举报、纠错和删除请求的可到达入口；具体处理时限由合规评审确定。
- NFR-COM-005：必须在上线前评估未成年人、逝者肖像/声音、名誉权、隐私、个人信息、深度合成和生成式 AI 服务相关义务。
- NFR-COM-006：不得在未完成专业评审时用本 PRD 声称已经满足全部中国大陆法律法规。

### 14.5 可靠性与可观察性

- NFR-OBS-001：每次角色处理、实时会话和轮次必须有可关联的诊断 ID。
- NFR-OBS-002：记录阶段、状态转换、耗时、错误类型、供应商事件或日志 ID、输入输出结构计数，不记录敏感正文和原始媒体。
- NFR-OBS-003：外部供应商不可用时，角色页面和通话页面必须快速失败并给出恢复路径，不得无限加载。
- NFR-OBS-004：对象存储、任务队列、数据库、实时网关和供应商连接失败必须能区分定位。
- NFR-OBS-005：重复回调、页面重试和网络抖动不得重复扣费、重复发布或创建重复角色版本。

### 14.6 兼容性与可访问性

- NFR-COMP-001：正式支持的浏览器和最低版本在上线前确定并测试；当前 Windows Chrome 验收不能替代手机浏览器验收。
- NFR-COMP-002：麦克风不可用时，页面必须保持可退出和可理解，不能只靠动画表达状态。
- NFR-COMP-003：关键状态和错误必须有文字，不得只依赖颜色或声音。

## 15. 验收标准

### 15.1 账号与授权

- AC-AUTH-001：用户令牌请求任意管理员接口，返回拒绝且不产生写操作。
- AC-AUTH-002：用户 A 直接请求未分配角色或用户 B 的角色链接，返回拒绝且不泄露角色详情。
- AC-AUTH-003：角色未发布、已撤回或分配已撤回时，用户列表不可见且建连失败。
- AC-AUTH-004：同一角色可同时分配给至少两个测试用户；撤回其中一个不影响另一个。

### 15.2 图片和动画

- AC-IMG-001：分别用侧脸、多人、嘴部遮挡、双眼缺失和严重模糊样本测试，系统均在生成前拒绝并给出对应原因。
- AC-IMG-002：用五官完整但无肩膀的样本测试，系统允许进入处理并产生自然肩部扩展供管理员审核。
- AC-IMG-003：管理员未批准规范图时，角色无法发布；批准后生成不可变版本和内容摘要。
- AC-IMG-004：`image/` 下 6 张代表性图片均能通过基础输入校验；轻微张嘴、自然眼部差异、年龄和远近景本身不会造成无理由拒绝。
- AC-VIS-001：在同一画布和渲染配置中对嘴巴闭合、小、中、大及眼睛睁闭帧进行像素差分，嘴眼遮罩并集之外差异像素数为 0。
- AC-VIS-002：静音基准显示自然闭嘴、非严肃、非明显抿嘴；管理员人工验收通过。
- AC-VIS-003：播放有声测试音频时嘴巴随音量变化，静音后回到闭合；使用实际输出播放链而不是用户麦克风。
- AC-VIS-004：连续观察包含至少一次完整自然眨眼，且间隔不是明显固定帧循环；具体观察时长在视觉测试方案中固定。
- AC-VIS-005：390×844 或等效窄屏下，五官完整可见，通话状态和结束按钮不遮挡嘴眼。
- AC-VIS-006：6 张代表性图片均产生自然闭嘴的静音规范图；管理员能够逐张对照原图确认身份、年龄特征、衣服和背景未被无目的改变。
- AC-VIS-007：对 6 张图片逐张运行嘴部四级、眨眼和嘴眼组合像素差分，允许遮罩并集之外的差异像素数均为 0。
- AC-VIS-008：6 张图片在典型手机窄屏中五官均完整可见；远景样本完成合理构图，近景样本不裁掉眼睛或嘴巴。

### 15.3 音色复刻

- AC-VOICE-001：上传不符合当前模型录音配置的文件时，在调用供应商训练前拒绝并说明原因。
- AC-VOICE-002：训练流程记录同一 speaker ID 的状态、版本/次数、模型类型和错误；刷新页面不丢失状态。
- AC-VOICE-003：供应商返回失败时，角色进入可行动失败状态，管理员可重传；系统不进行无限重试。
- AC-VOICE-004：音色成功但未试听批准时，角色无法发布。
- AC-VOICE-005：管理员批准特定音色版本后，用户实时会话使用该版本；换音频后旧批准自动失效。

### 15.4 实时通话

- AC-CALL-001：用户开始通话时浏览器只弹出麦克风授权，不请求摄像头。
- AC-CALL-002：初始静音不产生 AI 回复；有效讲话后句末静音自动提交。
- AC-CALL-003：AI 回复期间说话不创建新一轮；页面明确表示当前不可打断。
- AC-CALL-004：输出音频流式播放，无明显重叠、变速、尖刺、长断裂或截尾；播放状态与嘴部动作同步。
- AC-CALL-005：回复完成后嘴巴闭合并重新进入监听；结束通话后麦克风、音频队列、渲染和供应商连接全部释放。
- AC-CALL-006：网络中断、麦克风拒绝和供应商错误分别展示可行动提示和诊断 ID。

### 15.5 记忆隔离

- AC-MEM-001：用户 A 与角色 X 建立特征记忆后，用户 B 与角色 X 的上下文中检索不到该内容。
- AC-MEM-002：用户 A 与角色 X 和角色 Y 的记忆互不串写。
- AC-MEM-003：伪造请求体中的 user_id 不能读取或写入其他用户记忆，服务器始终使用认证主体。
- AC-MEM-004：记忆服务失败时当前通话最多降级为临时上下文，不产生跨用户数据。

### 15.6 删除与合规

- AC-DEL-001：删除前页面列出受影响用户数、版本和外部音色；取消确认不产生删除。
- AC-DEL-002：删除开始后角色立即对用户不可见且禁止新会话；物理清理状态可追踪。
- AC-DEL-003：外部音色未成功删除或回收时，页面和审计均显示残留状态，不宣称彻底删除。
- AC-COM-001：无有效授权记录的照片或声音不能进入生成任务，也不能发布。
- AC-COM-002：用户进入角色详情或通话页时能明显看到 AI 生成/合成身份提示。

| G4 管理员审核 | 图片、动画、音色、性格均由管理员批准 | 不得发布 |
| G5 权限与隔离 | 服务器端角色授权、分配和记忆隔离测试通过 | 不对用户开放 |
| G6 实时通话 | 半双工、流式播放、嘴部驱动、眨眼、错误清理通过 | 不对用户开放通话 |
| G7 移动端 | 目标手机/浏览器/网络下完成功能、布局和性能验收 | 限定支持范围或继续修复 |

角色级发布还必须满足：

```text
图片批准
AND 动画资产批准
AND 音色批准且可用
AND 性格批准
AND 授权记录有效
AND 角色未处于删除或撤回状态
```

## 17. 风险清单与最易失败点

| ID | 风险/最易失败点 | 影响 | 预防与回退 |
| --- | --- | --- | --- |
| RISK-001 | AI 补肩时改变脸、衣服或背景 | 角色失真，管理员不接受 | 只在必要区域补全；保留原图对比；管理员批准；失败则重传或人工模板处理 |
| RISK-002 | 嘴眼资产边缘破绽、重影或遮罩越界 | “照片在动”效果不自然，违反像素合同 | 固定规范图、局部遮罩、组合预览、自动像素差分；不合格不发布 |
| RISK-003 | 用全帧生成方案导致背景和皮肤闪烁 | 直接违反其余像素不变 | MVP 禁止逐帧全画幅重绘；候选技术必须先通过 AC-VIS-001 |
| RISK-004 | 嘴部分析了用户麦克风而不是 AI 输出 | 用户说话时角色嘴动，AI 说话时不同步 | 驱动源绑定实际输出播放节点；加入静音和方向性测试 |
| RISK-005 | 音色 ID、版本、计费模式理解错误 | 训练不可逆、浪费额度或调用错误音色 | 接入前核对当前官方文档；保存 speaker ID 全状态；不可逆操作二次确认 |
| RISK-006 | 参考音频质量差 | 噪声、吞音、音色突变 | 上传前检查与明确录音指导；试听批准；允许在限制内重训 |
| RISK-007 | 角色共享导致记忆也被共享 | 严重隐私事故和人格串线 | 共享资产域与用户私有域分离；服务端隔离键；越权和串写自动测试 |
| RISK-008 | 只在前端做管理员/用户隔离 | 直接越权 | 所有资源和操作由服务器端授权，做 IDOR 测试 |
| RISK-009 | 手机浏览器音频策略、切后台或性能差异 | 无声、重复轮次、画布丢失 | 真实设备矩阵测试；显式恢复状态；低成本本地嘴眼驱动 |
| RISK-010 | 实时和生成外部 API 故障或限额 | 角色生成或通话不可用 | 阶段化错误、有限重试、配额监控、诊断 ID、可替换适配层 |
| RISK-011 | 未确认并发和成本就公网开放 | 服务拥塞或费用失控 | G8 前锁定 TBD-001；限流、排队、预算告警和容量压测 |
| RISK-012 | 肖像、声音、AI 标识或数据处理不合规 | 无法上线或产生重大责任 | 有效授权闸门、删除和投诉流程、AI 显式提示、上线前专业评审 |
| RISK-013 | 管理员删除共享角色时级联范围不透明 | 多用户同时失去服务或数据残留 | 删除前影响预览、逻辑下线、异步物理清理、审计与补偿 |
| RISK-014 | 把当前本地 Demo 验收当成生产能力 | 账号、移动端、并发和公网安全被遗漏 | 现状/目标分离，生产 Gate 必须重新验证 |

## 19. 技术方案边界

本产品不强制采用 Live2D，本 PRD 也不决定最终架构；但任何技术方案必须满足以下产品合同：

- 人像运行时是轻度可动 2D 画面，不是固定视频，也不是每帧全图生成；
- 只有嘴部和眼皮局部区域可变；
- 嘴部由 AI 输出音量驱动；
- 眼皮本地随机眨动；
- 多用户共享角色资产，私有记忆隔离；
- 图片和音色异步处理，管理员最终批准；
- 浏览器不持有供应商密钥；
- 移动端和中国大陆部署可用。

允许评估的候选实现包括 Live2D、定制 2D 图层/网格或其他能通过相同验收的方案。若采用 Live2D，必须单独完成 SDK、模型和商业分发许可审查；若采用其他方案，也不得降低像素不变、移动端性能或管理员可批量操作要求。

技术设计必须在开始大规模实现前提交：组件边界、数据模型、任务幂等、供应商适配、权限模型、记忆隔离、删除策略、容量估算、成本估算、测试策略和回退方案。

## 22. 变更控制

### 22.1 必须升级 PRD 版本的变化

- 增加或删除 MVP 模块；
- 改变管理员或用户权限；
- 改变规范图或像素不变的定义；
- 从音量口型升级为音素口型；
- 增加用户摄像头、打断、全双工、身体动作或知识库；
- 改变记忆隔离或数据使用范围；
- 改变真人照片、声音、会话和记忆的授权或删除政策；
- 将某个候选供应商或人像技术变成不可替换的产品前提；
- 改变核心验收、发布门槛、并发承诺或生产 SLA。

### 22.2 变更申请最少内容

每项变更必须记录：

1. 变更原因和用户价值；
2. 影响的 OBJ、FR、NFR、AC、Gate 和 TBD；
3. 影响的页面、数据、权限、外部服务、成本与排期；
4. 新增风险和回退方式；
5. 产品负责人批准记录；
6. PRD 新版本和变更日志。

### 22.3 开发防跑偏规则

- 开发任务必须引用至少一个 FR/NFR 和对应 AC；没有引用不得进入实施。
- 技术设计必须说明如何满足产品合同，而不是用技术名词替代验收。
- 测试用例必须引用 AC；所有 P0 验收未通过不得发布。
- 未决的 TBD 必须在其最晚决策点前关闭；未关闭时只能做不依赖该决策的工作。
- 发现需求缺口时必须新增或修改 PRD，经批准后再开发，禁止在代码中悄悄决定。
